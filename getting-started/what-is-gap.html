What is GAP?

GAP gives AI agents one safe, typed entry point to call REST APIs, SQL databases, gRPC services, GraphQL subgraphs, CLIs, and code repositories—without stuffing thousands of JSON tool definitions into the LLM context window.

What you'll learn

  • Why loading flat tool catalogs directly into prompts breaks down as your system grows.
  • Core GAP vocabulary: Gateway, Branch, Connector, Snapshot, and Principal.
  • Exact crossover boundary: when to use Direct-MCP vs. when GAP dominates.

Why Flat Agent Tooling Hits a Wall

Most agent integrations connect an LLM directly to individual Model Context Protocol (MCP) or HTTP endpoints. That works cleanly for 5–10 small tools, then fails in four predictable ways in production:

  • Context Explosion: Serializing 1,000 flat JSON Schema tools up front consumes 203,421 tokens before the user even asks a question.
  • N+1 Agent Waterfalls: Without a shared join planner, the model fetches a customer, loops through orders turn-by-turn, then queries notes separately—wasting latency and tokens.
  • Mutable Descriptions (Rug Pulls): If an untrusted upstream edits a tool description after approval to inject hidden instructions, flat clients forward the poisoned text straight to the LLM.
  • Probabilistic Authorization Leaks: Letting an LLM or neural classifier enforce access control introduces bypass risk. Access decisions must be deterministic code.

When Direct-MCP Is Still Simpler (Honest Crossover)

Transparent Benchmark Result (ADR-021)

If your agent has 50 or fewer simple read tools and your LLM provider keeps 0.10x prompt prefix caching warm, Direct-MCP uses fewer tokens on single-step lookups (547.2 vs. 4,691.9 tokens at N=10).

Adopt GAP immediately once you exceed ~200 tools, need cross-backend joins, navigate code ASTs, or require zero-trust security guarantees (Cedar approvals, SSRF EgressGuard, rug-pull freeze). Explore exact numbers in the Crossover Calculator.

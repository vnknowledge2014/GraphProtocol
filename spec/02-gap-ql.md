# GAP Specification — 02 GAP-QL (the client-facing language)

Normative IDs `GQL-*`. Rationale: ADR-001, 003, 010, 023. Replaces the 21-undefined-nonterminal EBNF of the earlier draft.

## 1. Definition: a profile of GraphQL
- **GQL-001** A GAP-QL request document MUST be a valid GraphQL *executable document* and a GAP schema MUST be valid GraphQL SDL, per the GraphQL `September 2025 Edition` pinned in `third_party/MANIFEST.toml` and `docs/evidence/crate-versions.md`. GAP adds **only**: (a) the reserved `gap` namespace (§3), (b) introspection extensions `__search`/`__metaGraph` (§4), (c) the directives in §5 (plus `@defer`/`@stream` only when the `incremental` feature is enabled, RUN-062), (d) request/response `extensions.gap` (§6), (e) limits and error codes (§8–§10).
- **GQL-002** Implementations MUST use a conforming GraphQL parser/validator (reference: `apollo-compiler`) and MUST NOT accept documents that a conforming validator rejects, except where §7 mandates identical-looking errors for hidden elements.
- **GQL-003** Transport: *GraphQL over HTTP* with `application/graphql-response+json` (and `application/json` fallback); `POST` required, `GET` allowed only for persisted operations; subscriptions via `graphql-sse` (distinct-connections mode) over HTTP/2. WebSocket subscriptions are out of scope (ADR-019).
- **GQL-004** Field/argument/type names MUST NOT begin with `__` except introspection; branch schemas MUST NOT define the root fields `gap`, `__search`, `__metaGraph`, or the types listed in §3 (composition error `GAP_RESERVED_NAME`).

## 2. Why a profile (informative)
LLMs know GraphQL; tooling (GraphiQL, codegen, linting) works unchanged; multi-hop graph walks, discovery and tasks are ordinary typed fields, so validation errors give agents precise self-repair hints (§9).

## 3. Reserved namespace and built-in schema
The following SDL is part of every supergraph (generated by the composer, not authored by branches). `@oneOf` is built-in in GraphQL September 2025 (Appendix D); it is declared explicitly below because the parser in use may not pre-load it (`third_party/specs/SPEC-NOTES.md` Q-16). The fenced block is embedded verbatim by `gap-ql`, so keep comments about it outside the fence.

```graphql
scalar DateTime            # RFC 3339 UTC
scalar JSON                # any JSON value; used only for open-ended node properties
scalar Cursor              # opaque, base64url, server-signed (tamper-evident)

directive @oneOf on INPUT_OBJECT

enum Direction        { OUTBOUND INBOUND BOTH }
enum TraverseStrategy { BFS DFS SHORTEST WEIGHTED }
enum ContextScope     { PRIVATE TASK GROUP GLOBAL EPHEMERAL }
enum ElementKind      { OPERATION TYPE FIELD NODE_CATEGORY EXAMPLE }
enum ResolveOutcome   { CONFIDENT AMBIGUOUS ABSTAINED }
enum AbstentionReason { NO_MATCH LOW_CONFIDENCE EMPTY_VISIBLE_SET MODEL_UNAVAILABLE }
enum SideEffectLevel  { NONE REVERSIBLE IRREVERSIBLE UNKNOWN }
enum TrustTier        { T0 T1 T2 }
enum BranchStatus     { ACTIVE DRIFT QUARANTINED DISABLED }
enum Protocol         { SQL REST GRPC GRAPHQL MCP A2A CLI CODE_GRAPH CUSTOM }
enum TaskState        { SUBMITTED WORKING INPUT_REQUIRED AUTH_REQUIRED COMPLETED FAILED CANCELED REJECTED }
enum TaskStrategy     { SINGLE PARALLEL SEQUENTIAL DAG }
enum ApprovalDecision { APPROVE DENY }

type Query        { gap: GapQuery! }
type Mutation     { gap: GapMutation! }
type Subscription { gapTaskEvents(taskId: ID!, fromSeq: Int = 0): TaskEvent! }

type GapQuery {
  "Intent -> ranked capability groups with executable skeletons, or an explicit abstention. Never executes."
  resolve(intent: String!, constraints: ResolveConstraints): Resolution!
  "Multi-hop walk over graph branches (code/doc/context graphs). Bounded by maxDepth and budget."
  traverse(input: TraverseInput!): Subgraph!
  node(ref: NodeRef!): GapNode
  task(id: ID!): Task
  tasks(filter: TaskFilter, first: Int = 20, after: Cursor): TaskConnection!
  "Same data as __metaGraph, for clients that cannot send introspection-style fields."
  metaGraph: MetaGraph!
  "Plan explanation for a document (no execution). Subject to authorization."
  explain(document: String!, variables: JSON): PlanExplanation!
  proposals(status: [ProposalStatus!], first: Int = 20, after: Cursor): ProposalConnection!
}

type GapMutation {
  submitTask(input: SubmitTaskInput!): Task!
  cancelTask(id: ID!, reason: String): Task!
  decideApproval(taskId: ID!, approvalId: ID!, decision: ApprovalDecision!, note: String): Task!
  "Ingestion is propose-only (ADR-013)."
  proposeSource(input: ProposeSourceInput!): Proposal!
  decideProposal(id: ID!, decision: ApprovalDecision!, note: String, breakingChangeAck: Boolean = false): Proposal!
}

# ---------- discovery ----------
input ResolveConstraints { branches: [ID!], maxSideEffect: SideEffectLevel = NONE, maxCandidates: Int = 5, budgetTokens: Int }
type Resolution {
  outcome: ResolveOutcome!
  candidates: [Candidate!]!          # empty iff ABSTAINED
  abstentionReason: AbstentionReason
  calibrationId: String              # null when router is baseline-uncalibrated
  router: String!                    # "baseline" | "s1:<model-id>"
  tokensEstimate: Int!
}
type Candidate {
  groupId: ID!  score: Float!  probability: Float   # probability only when calibrated
  operation: OperationRef!  skeleton: String!  variablesSchema: JSON!  sdl: String!
  sideEffect: SideEffectLevel!  trust: TrustTier!  why: String
}
type OperationRef { id: ID!  branch: ID!  kind: String! }

# ---------- graph walk ----------
input NodeRef @oneOf { id: ID  key: NodeKey }
input NodeKey { type: String!  value: JSON! }
input EdgeFilter { types: [String!]  where: Predicate }
input TraverseInput {
  from: NodeRef!  through: EdgeFilter  direction: Direction = OUTBOUND
  maxDepth: Int!                  # 1..16 (GQL-040)
  strategy: TraverseStrategy = BFS  asOf: DateTime  where: Predicate
  scopes: [ContextScope!]         # narrows visibility only (GQL-043)
  first: Int = 100  after: Cursor
  returnFields: [String!]         # projection of node props (token control)
}
input Predicate @oneOf {          # recursive boolean algebra over props/paths
  and: [Predicate!]  or: [Predicate!]  not: Predicate
  eq: Compare  ne: Compare  gt: Compare  gte: Compare  lt: Compare  lte: Compare
  in: CompareList  contains: Compare  startsWith: Compare  exists: String
}
input Compare     { path: String!  value: JSON! }
input CompareList { path: String!  values: [JSON!]! }
type Subgraph { nodes: [GapNode!]!  edges: [GapEdge!]!  pageInfo: PageInfo!  truncated: Boolean!  stats: TraverseStats! }
type GapNode  { id: ID!  type: String!  label: String!  props: JSON  provenance: Provenance  validFrom: DateTime  validTo: DateTime  scope: ContextScope }
type GapEdge  { id: ID!  type: String!  from: ID!  to: ID!  props: JSON  confidence: Float  resolution: EdgeResolution!  provenance: Provenance }
enum EdgeResolution { EXACT HEURISTIC }
type TraverseStats { visited: Int!  returned: Int!  depthReached: Int!  tokensEstimate: Int! }
type PageInfo { hasNextPage: Boolean!  endCursor: Cursor }
type Provenance { source: String!  descHash: String  confidence: Float  extractedAt: DateTime  agent: String }

# ---------- tasks (ADR-016) ----------
input SubmitTaskInput {
  contextId: ID  goal: String  strategy: TaskStrategy = SINGLE
  steps: [TaskStepInput!]!   deadlineMs: Int  idempotencyKey: String
}
input TaskStepInput {
  id: ID!  dependsOn: [ID!]
  gapql: String            # executed through the normal pipeline as the submitting principal
  variables: JSON
  delegate: DelegateInput  # exactly one of gapql/delegate
}
input DelegateInput { branch: ID!  message: JSON!  expectArtifacts: [String!] }
type Task {
  id: ID!  contextId: ID  state: TaskState!  strategy: TaskStrategy!
  steps: [TaskStep!]!  artifacts: [Artifact!]!  pendingApproval: Approval
  createdAt: DateTime!  updatedAt: DateTime!  deadlineAt: DateTime  lastSeq: Int!
  error: TaskError
}
type TaskStep { id: ID!  state: TaskState!  result: JSON  error: TaskError }
type Artifact { id: ID!  name: String  mediaType: String!  data: JSON  uri: String  sha256: String }
type Approval { id: ID!  action: String!  summary: String!  sideEffect: SideEffectLevel!  expiresAt: DateTime! }
type TaskError { code: String!  message: String!  retryable: Boolean! }
type TaskEvent { seq: Int!  taskId: ID!  at: DateTime!  state: TaskState!  stepId: ID  message: String  artifact: Artifact }
type TaskConnection { nodes: [Task!]!  pageInfo: PageInfo! }
input TaskFilter { state: [TaskState!]  contextId: ID }

# ---------- meta / ingestion ----------
type MetaGraph { generation: Int!  branches: [MetaBranch!]!  groupCount: Int!  tokensEstimate: Int! }
type MetaBranch {
  id: ID!  protocol: Protocol!  trust: TrustTier!  status: BranchStatus!
  synopsis: String!  nodeCategories: [String!]!  edgePredicates: [String!]!
  operationCount: Int!  readOnlyCount: Int!  mutatingCount: Int!
}
type PlanExplanation { plan: JSON!  branchesTouched: [ID!]!  estimatedCost: Int!  pushdowns: [String!]!  warnings: [String!]! }
input ProposeSourceInput { kind: Protocol!  location: String!  name: String  trust: TrustTier = T2  notes: String }
enum ProposalStatus { PROPOSED EXTRACTING ENRICHING VERIFYING STAGED AWAITING_APPROVAL PROMOTING ACTIVE WATCHING STABLE REJECTED FAILED ROLLED_BACK }
type Proposal { id: ID!  status: ProposalStatus!  branch: ID  kind: Protocol!  location: String!  report: JSON  createdAt: DateTime!  updatedAt: DateTime! }
type ProposalConnection { nodes: [Proposal!]!  pageInfo: PageInfo! }
```
- **GQL-010** Every type/field above MUST be present with these names and types in a conforming server's introspection (subject to §7 filtering). Servers MAY add optional fields (clients MUST ignore unknown fields in responses they did not select — standard GraphQL).
- **GQL-011** `gap.resolve` and `__search` MUST NOT execute any branch operation and MUST NOT return elements invisible to the caller (INV-05).
- **GQL-012** `Candidate.skeleton` MUST be a document that passes validation against the *current* snapshot and uses only variables declared in `variablesSchema`.

## 4. Introspection extensions (implicit root fields, not declared in SDL)
```graphql
# implicit on Query, visible to introspection like __schema/__type
__search(query: String!, first: Int = 5, kinds: [ElementKind!], branches: [ID!], budgetTokens: Int): SearchResult!
__metaGraph: MetaGraph!

type SearchResult { hits: [SearchHit!]!  tokensEstimate: Int!  abstained: Boolean! }
type SearchHit { score: Float!  kind: ElementKind!  name: String!  path: String!  branch: ID!  group: ID
                 description: String!  sdl: String!  sideEffect: SideEffectLevel  trust: TrustTier! }
```
- **GQL-020** `__search` ranks with the hybrid index only (deterministic for a fixed snapshot and query; no S1); `abstained = true` iff no hit reaches `retrieval.min_score` (config; default 0.15 after RRF normalization to [0,1]).
- **GQL-021** `SearchHit.sdl` MUST be the minimal self-contained SDL fragment needed to write a valid query for the element (the element plus the types it references, transitively, truncated at `budgetTokens`; if truncated, a trailing comment `# truncated: use __type(name: "X")`).
- **GQL-022** `tokensEstimate` is computed with the server's configured tokenizer-agnostic estimator `ceil(utf8_bytes / 3.6)` unless a specific tokenizer id is requested via `extensions.gap.tokenizer`; it is an estimate and MUST be labelled so in docs.
- **GQL-023** `__metaGraph` (L0) MUST list at most `limits.metagraph_branches` (default 100) branches ordered by `operationCount` desc, then id; synopsis ≤ 24 model tokens (≈ 90 bytes) each.
- **GQL-024** Standard `__schema`/`__type` remain available (L2) and are filtered per §7.

## 5. Directives
**Type-system directives (set by composer/ingestion; authors of branch schemas MAY use those marked ✎):**
```graphql
directive @branch(id: ID!, uid: ID!, protocol: Protocol!, trust: TrustTier!) on OBJECT | FIELD_DEFINITION
directive @capabilityGroup(id: ID!) on FIELD_DEFINITION
directive @key(fields: String!) repeatable on OBJECT                                   # ✎ entity key
directive @join(to: String!, on: [JoinKey!]!, cardinality: Cardinality!,
                strategy: JoinStrategy = FOREACH_BATCH, status: JoinStatus = PROPOSED,
                evidence: JSON) on FIELD_DEFINITION                                    # status managed by gates (ADR-012)
directive @sideEffect(level: SideEffectLevel!, idempotent: Boolean = false, dryRun: Boolean = false) on FIELD_DEFINITION   # ✎ (T0/T1 only)
directive @compensate(with: String!) on FIELD_DEFINITION                                # ✎ operation id that undoes this one
directive @auth(policy: String, scopes: [String!]) on OBJECT | FIELD_DEFINITION         # ✎
directive @cost(weight: Int = 1, listSize: Int, perKey: Int) on FIELD_DEFINITION        # ✎
directive @provenance(source: String!, descHash: String!, confidence: Float, extractedAt: DateTime) on OBJECT | FIELD_DEFINITION
directive @temporal(validFrom: String, validTo: String, supersedes: String) on OBJECT | FIELD_DEFINITION   # ✎
directive @pii(kind: String!) on FIELD_DEFINITION                                       # ✎ redaction policy hook
input JoinKey { from: String!, to: String! }
enum Cardinality { ONE_TO_ONE MANY_TO_ONE ONE_TO_MANY }   # MANY_TO_MANY is not expressible (RUN-021)
enum JoinStrategy { FOREACH_BATCH REMOTE_PREDICATE }
enum JoinStatus { PROPOSED VERIFIED ACTIVE DEPRECATED }
```
**Executable directives:**
```graphql
directive @budget(ms: Int, tokens: Int, costUnits: Int, failFast: Boolean = false) on QUERY | MUTATION | SUBSCRIPTION
directive @dryRun on MUTATION
directive @format(as: Format = JSON) on FIELD            # COLUMNAR is extension X-1 (M7)
enum Format { JSON COLUMNAR }
```
- **GQL-030** A server MUST ignore `@branch`, `@capabilityGroup`, `@provenance`, `@join(status:)` supplied by T1/T2 branch authors (they are overwritten by composition); supplying them is a warning `GAP_DIRECTIVE_IGNORED`.
- **GQL-031** Only `status: ACTIVE` joins are planned; `PROPOSED/VERIFIED/DEPRECATED` appear in introspection only for principals with `admin:schema` (INV-06).
- **GQL-032** `@sideEffect` on fields of T2 branches is forced to `UNKNOWN` regardless of authored value (ADR-015).

## 6. Request and response envelopes
Request `extensions.gap` (all optional):
```json
{ "version": "gap/0.1", "features": ["tokensEstimate"], "requires": [],
  "deadlineMs": 15000, "budget": { "tokens": 4000, "costUnits": 5000 },
  "idempotencyKey": "01J…", "tokenizer": "cl100k_base",
  "trace": { "traceparent": "00-…", "hop": 0, "path": ["node-a"] }, "explain": false }
```
Tenant and principal are derived from authentication, never from the body (SEC-010). Response `extensions.gap`:
```json
{ "generation": 412, "features": ["tokensEstimate"], "tokensEstimate": 187,
  "cost": { "planned": 120, "actual": 96 }, "partial": false,
  "warnings": [{ "code": "GAP_PUSHDOWN_FALLBACK", "message": "…", "path": ["a","b"] }],
  "plan": { } }      # only when explain=true and authorized
```
- **GQL-050** Servers MUST include `generation` and, when the client set a budget, `tokensEstimate` for the `data` portion.
- **GQL-051** If `data` is partially populated because a branch call failed, `partial = true`, the affected fields are `null` (or the nearest nullable ancestor per GraphQL error propagation) and `errors[]` contains one entry per failed *chunk/branch* with `path`.

## 7. Operation modes, persisted operations and visibility
- **GQL-060** `gateway.operation_mode` ∈ `open | hybrid | safelist` (default `open` in dev profile, `hybrid` in prod profile). `hybrid`: arbitrary documents allowed if they contain no mutation or task submission; mutations only via registered operations. `safelist`: only registered operations. Violations → `GAP_OPERATION_NOT_ALLOWED`.
- **GQL-061** Persisted operations use SHA-256 ids (`extensions.persistedQuery.sha256Hash`, Apollo APQ-compatible). Registration of new operations is an admin action recorded in the audit log; the MCP facade tool `gap_describe` can return the registered operation catalogue for agents.
- **GQL-062** *Visibility filtering:* introspection, `__search`, `__metaGraph` and validation error messages MUST behave as if elements the caller may not `see` (policy action `Discover`) do not exist. A query naming a hidden field MUST produce the same error shape and message as an unknown field (no existence oracle), including `didYouMean` computed only from visible names.

## 8. Limits (configurable within range)
| Limit | Default | Range | Error |
|---|---|---|---|
| Max selection depth | 12 | 1–32 | `GAP_DEPTH_EXCEEDED` |
| Max aliases per document | 50 | 1–500 | `GAP_COMPLEXITY_EXCEEDED` |
| Max root fields | 20 | 1–100 | `GAP_COMPLEXITY_EXCEEDED` |
| Max cost units | 10 000 | 100–1 000 000 | `GAP_COMPLEXITY_EXCEEDED` |
| Max request body | 1 MiB | 16 KiB–16 MiB | HTTP 413 (`gap-ql` reports `GAP_COMPLEXITY_EXCEEDED`; the transport translates it) |
| Max response body | 4 MiB | 64 KiB–64 MiB | `GAP_RESPONSE_TOO_LARGE` |
| Default list size when unspecified | 100 | 1–1 000 | (clamp + warning) |
| `traverse.maxDepth` | ≤ 16 | 1–16 hard | `GAP_DEPTH_EXCEEDED` (GQL-040) |
| Variables per document | 100 | 1–1 000 | `GAP_VALIDATION_ERROR` |
| Request deadline | 30 000 ms | 100–600 000 | `GAP_DEADLINE_EXCEEDED` |

- **GQL-040** `traverse.maxDepth` MUST be in 1..16 (hard cap, not configurable above 16); `first` ≤ 1,000; larger values are rejected with `GAP_DEPTH_EXCEEDED` / `GAP_COMPLEXITY_EXCEEDED` before any branch call.
- **GQL-041** *Cost model:* `cost(F) = w(F) + m(F)·Σ cost(child)` where `w` = `@cost.weight` (default 1), `m(F)` = effective list size = `min(arg first/limit/pageSize if present, @cost.listSize, default_list)` for list-typed fields else 1; join fields add `perKey · expected_keys` where `expected_keys = m(parent)`; `traverse` costs `visited_bound = Σ_{d=1..maxDepth} min(first, branching_cap)^d` truncated by `first`. The planner computes cost before execution (RUN-005); exceeding the budget rejects the whole document. `branching_cap` defaults to 8 and MAY be overridden by the planner.
- **GQL-042** Cycles in the *schema* are legal. Unbounded *expansion* is prevented by depth and cost limits at run time; the composer additionally rejects joins forming a cycle with no `maxDepth`-bounded entry (error `GAP_CYCLE_UNBOUNDED`) — this replaces the old "Tarjan SCC ⇒ max_depth 16" rule.
- **GQL-043** *Scopes (ADR-025, D-007).* `TraverseInput.scopes` can only narrow the set of nodes already visible to the caller under ING-065, never widen it; omitted means "every visible scope"; an empty list is a `GAP_VALIDATION_ERROR`. `GapNode.scope` is returned for visible nodes only. `TraverseStrategy.WEIGHTED` semantics are fixed by ING-067; interval temporal queries are not part of 1.0 (only `asOf`).

## 9. Self-repair hints for LLM callers
- **GQL-070** Validation errors MUST include `extensions.suggestion` when derivable: `didYouMean: [..]` (edit distance ≤ 2 over *visible* names, then top-3 `__search` hits), `template` (a minimal valid selection for the parent type), `missingArguments: [..]`.
- **GQL-071** `GAP_INSUFFICIENT_EVIDENCE` carries `extensions.suggestion = { nextStep: "propose_source" | "rephrase" | "ask_user", examples: [..] }`.
- **GQL-072** Error messages MUST be ≤ 300 characters and contain no secret or hidden-element names (INV-15, GQL-062).

## 10. Error codes (stable enum)
All errors: `{ message, path?, locations?, extensions: { code, retry: { retryable, afterMs? }, suggestion?, correlationId } }`. Per GraphQL-over-HTTP (`application/graphql-response+json`), request errors raised before execution omit `data` and return `4xx`/`5xx` (`400` for JSON or GraphQL parse failures, `422` for GraphQL validation, operation-resolution or variable-coercion failures); on `graphql-sse` distinct-connections streams such errors are sent as `event: next` `{errors}` on a `200 text/event-stream`. Execution-phase errors include `data` and return `200` with `errors[]` (ADR-023).

| Code | Class | Retryable | Notes |
|---|---|---|---|
| `GAP_PARSE_ERROR`, `GAP_VALIDATION_ERROR` (+ `GAP_UNKNOWN_FIELD`, `GAP_UNKNOWN_ARGUMENT`, `GAP_MISSING_ARGUMENT`, `GAP_TYPE_MISMATCH`) | request | no | `data` omitted; HTTP `400` (`GAP_PARSE_ERROR`, invalid JSON) or `422` (validation, coercion, operation resolution) with `application/graphql-response+json` |

## 11. Conformance fixtures
`conformance/gql/*.json`:
```json
{ "name": "unknown field gets didYouMean",
  "class": ["Core"], "spec": ["GQL-070","GQL-062"],
  "schema": "fixtures/billing.graphql",          // composed supergraph used by the test server
  "principal": "agent-readonly",
  "request": { "query": "{ billing { invoce(id:\"1\"){total} } }" },
  "expect": { "status": 422,
              "errors": [{ "extensions": { "code": "GAP_UNKNOWN_FIELD", "suggestion": { "didYouMean": ["invoice"] } } }],
              "dataNull": true } }
```
Matching semantics: `expect` is a *subset match* (objects: all listed keys equal; arrays: element-wise subset in order unless `"unordered": true`). The runner reports spec-ID coverage.

Precisely (so that any implementation of a runner agrees):
- **Observed response.** The runner matches `expect` against the JSON object `{ "status": <HTTP status code>, "data": <response data, null when absent>, "errors": <response errors, [] when absent>, "extensions": <response extensions, {} when absent>, "headers": <lower-cased header name → string>, "dataNull": <true iff data is null or absent> }`. `dataNull` is therefore derived, never sent by the server.
- **Objects:** every key listed in `expect` MUST exist in the observed object and match recursively; unlisted observed keys are ignored. **Scalars and `null`:** equal (numbers compare by value). **Arrays:** ordered by default: same length and `expect[i]` matches `observed[i]` for every `i` (an expected array is *not* a prefix or subsequence). To match regardless of order, write the expected array as the wrapper object `{ "unordered": true, "items": [ … ] }`: same length and a one-to-one pairing exists in which every expected item matches its paired observed item.
- **`steps`.** A fixture has either `request` + `expect` or `steps`: a non-empty list of `{ "request": …, "expect": … }` executed in order on the same principal and session, each matched against that step's own observed response; the first failing step fails the fixture and later steps are not run.
- **Coverage.** The report lists, per spec id named in `spec`, the fixtures that cover it and their verdicts; an id counts as covered only if at least one fixture naming it passed.
- **Numbers.** Numbers compare by exact mathematical value: integers that fit in 64 bits are compared as integers (`9007199254740992` ≠ `9007199254740993`), an integer equals a float with the same value (`1` = `1.0`, `0` = `-0.0`), everything else is compared as IEEE-754 binary64.
- **Response decoding.** The runner sends exactly one HTTP request per request/step, never follows redirects (a 3xx is the observed response), uses no proxy, and applies a 10 s connect timeout and a 30 s total timeout; any transport failure or timeout makes the fixture's verdict `error`. Repeated response headers are folded into one string joined by `", "` in wire order. A body that parses as a JSON object supplies `data`/`errors`/`extensions`; an empty body, or a non-JSON body whose `Content-Type` does not contain `json`, is observed as `data: null, errors: [], extensions: {}`; a body that is malformed JSON while `Content-Type` contains `json`, or valid JSON that is not an object, makes the verdict `error`.
- **Fixture validity.** `spec` is a non-empty array of ids matching `^[A-Z][A-Z0-9]*-[0-9]{2,3}$` (duplicates inside one fixture collapse). An optional string field (`principal`, `schema`) set to `null` is treated as absent. A fixture that names a `principal` the runner has no bearer token for gets verdict `error` and is never skipped; no request is sent for it. A run that executes zero fixtures (empty directory, or `--class` matching nothing) is a usage error (exit 2), never a pass.

## 12. Extension X-1: columnar lists (scheduled M7)
`@format(as: COLUMNAR)` on a list field returns `{"columns":["id","total"],"rows":[["1",10.5],…]}` instead of repeated object keys, targeted at token reduction for large homogeneous lists; clients expand losslessly. Normative details are deferred until GAP-Bench shows ≥ 20% token reduction on the large-list suite.

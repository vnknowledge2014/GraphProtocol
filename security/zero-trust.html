Zero-Trust Governance & Cedar

GAP treats every external upstream tool description, response payload, and network destination as potentially hostile—enforcing Cedar default-deny policies, desc_hash rug-pull pinning, SSRF egress guards, OS sandboxing, and tamper-evident BLAKE3 audit logs.

What you'll learn

  • Classify backends into T0, T1, and T2 trust tiers and inspect Cedar two-person mutation policies.
  • Prevent MCP rug pulls with DriftMonitor and prompt smuggling with <gap:untrusted> envelopes.
  • Stop DNS-rebinding / cloud-metadata SSRF (169.254.169.254) using EgressGuard.

Trust Tiers & Cedar Access Rules (INV-04, INV-11)

Every upstream branch sits in an explicit trust tier:

  • T0 (Platform Signed): Verified Ed25519 branch.manifest.json signature rooted in configured organization public keys. Any signature failure immediately demotes the branch to T2.
  • T1 (Admin Approved): Reviewed upstream APIs pinned by canonical schema digest (spec_hash) and operation description hash (desc_hash).
  • T2 (Untrusted / External): Sandboxed via OS namespaces (Bubblewrap / nsjail on Linux, Seatbelt on macOS)—failing closed if no OS sandbox is present—and blocked from joining across trust domains (INV-07).

Access decisions are pure functions evaluated in Cedar (policies/default.cedar) where forbid always beats permit:

  • Zero model involvement: No LLM confidence score can relax Cedar enforcement (INV-04), and spoofed MCP annotations like readOnlyHint: true are ignored.

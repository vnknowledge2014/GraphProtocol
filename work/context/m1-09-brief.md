## 3. Design (binding shape; names inside a module are yours unless stated)

Crate header as the other crates. Modules under `outbound/`:

1. `jsonrpc` — frames (`Request{id,method,params}`, `Notification`, `Response{result|error}`), id allocation (monotonic per connection), strict decoding with a size cap (default 4 MiB per frame) and no panic on any byte sequence (proptest), error object mapping (`-32700..-32603`, the MCP codes `-32020` HeaderMismatch, `-32021`, `-32022` UnsupportedProtocolVersion: see SPEC-NOTES).
2. `transport` — `trait McpTransport: Send + Sync + 'static` (RPITIT, like `Upstream`): `request(method, params, CallOptions{timeout, cancel}) -> Future<Result<Value, McpError>>` and `notify(method, params)`. `McpError` carries no server text that could leak (sanitised, clipped). Two implementations:
   * `StdioTransport<R, W>` generic over `AsyncBufRead`/`AsyncWrite` (newline-delimited JSON-RPC, concurrent requests matched by id, a bounded line length, EOF fails all pending calls, stdout carries protocol lines only, stderr is drained and dropped with a counter); cancellation sends `notifications/cancelled {requestId, reason}` and forgets the id (CMP-012, SPEC-NOTES Q-8).
     `StdioLauncher` spawns the child with `tokio::process::Command` **only** through `LaunchPolicy`: `LaunchPolicy::Refuse` (the default and the only policy for non-dev profiles: always an error), or `LaunchPolicy::DevAllowList(Vec<AllowedBinary{path (absolute), sha256 (hex), args}>)`: the path must be absolute, the file's sha256 must equal the entry (hash the file before exec, compare in constant time), the environment is cleared except an explicit list,
     no shell, no `$PATH` search, a kill-on-drop child. The launcher itself is covered by `#[ignore = "needs child processes"]` tests against a tiny stub server under `tests/fixtures/mcp/` that the reviewer runs; everything else uses `tokio::io::duplex`.
   * `HttpTransport<C: HttpPost>` where `trait HttpPost` is the minimal client (`post(url_path, headers, body, timeout) -> Result<HttpReply>`; the reply is either a JSON body or an SSE stream of events, both bounded) with `ReqwestPost` (no TLS, https refused at construction, redirects off, body cap enforced while reading) and an in-memory fake for tests. Headers per CMP-010: `Content-Type`, `Accept: application/json, text/event-stream`, `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name` (on `tools/call`/`resources/read`). Cancellation on `2026-07-28` closes the response stream (drop the future/stream), on `2025-11-25` HTTP it also sends `notifications/cancelled`.
3. `session` — era negotiation (CMP-010): probe `2026-07-28` (`server/discover` on stdio; headers + `_meta` on HTTP, treating HTTP 400 with `-32020..-32022` and a JSON-RPC `-32601`/`-32602` on stdio as "not this era"), else fall back to `2025-11-25` (`initialize`, `notifications/initialized`, `MCP-Session-Id` echo, `404` -> one re-initialise, `DELETE` on close). Every `2026-07-28` request carries `params._meta["io.modelcontextprotocol/protocolVersion"]` and
   `["io.modelcontextprotocol/clientCapabilities"]` with `roots` and `sampling` omitted (CMP-013). A server that answers `sampling/createMessage` or `roots/list` is refused (an error, never an LLM call). Result envelopes: a missing `resultType` is `complete` in the legacy era and an error in the modern one (SPEC-NOTES section (c)); `ttlMs`/`cacheScope` are read and kept on the discovery result.
4. `map` — CMP-011/012: tool -> `OperationDescriptor` (name sanitised to `[A-Za-z_][A-Za-z0-9_]*` deterministically with collision suffixes; `kind = QUERY` unless an admin classification is configured (`OpClassification` map in the config); `input_schema = tool.inputSchema`; `output_schema = tool.outputSchema` or `{}`; `annotations` kept as **untrusted** strings (`readOnlyHint` etc. never change `kind` or `side_effect_hint`: an admin config entry may);
   `description` is untrusted text), resources -> a node category `McpResource{uri,name,mimeType}` in `MetaSummary.node_categories`, readable through a reserved read operation `mcp_read_resource(uri)`; prompts ignored. The SDL: one root field per tool under `type Query`/`type Mutation` (by classified kind) with arguments from the JSON Schema (scalars, enums, lists, nested objects as input types named after the tool; anything else `JSON`; the SDL must pass `gap_ql::schema::with_gap_builtins`), result type `JSON` unless `outputSchema` is a simple object. Result mapping: prefer `structuredContent`; else a single text block that parses as JSON; else `{"text": ...}`; `isError: true` -> `UPSTREAM_ERROR` with sanitised clipped text.
   Pages are drained until `nextCursor` is absent with a hard page cap (default 100) and item cap (default 10,000). `desc_hash` is GAP's job (never computed here).
5. `connector` — `McpConnector<T: McpTransport>` implements `gap_ngc_sdk::Connector`: `describe` (cached from the last discovery, `known_spec_hash` -> `not_modified`; `spec_hash` = hex blake3 of the canonical text of the sorted tool list), `query` (solo and `foreach`), `health`, and `refresh(&self)`. `foreach` (CMP-015, NGC-020/026): bounded fan-out through `gap_ngc_sdk::foreach` with `Limits.max_batch_size = 64`, concurrency default 4, `annotations["batch"] = "emulated"`, `upstream_calls` equal to the number of requests actually sent (every retry counts); a failing key is isolated.
   Timeouts: per call `min(config.call_timeout, remaining deadline)`; deadline already past -> `DEADLINE_EXCEEDED` without a request; cancel and deadline drop the in-flight request and send the cancellation of 2. Retries: none for `tools/call` (a tool may have side effects: MCP gives no idempotency), one retry only for discovery calls on connection failure. `Limits.max_in_flight` is enforced with `RESOURCE_EXHAUSTED` + `retry_after_ms`, no queueing. Error text never contains server-provided text beyond a clipped sanitised message, never credentials, never the launch path.
6. `config` — `McpConfig` with `Debug` redaction of every secret, validated at construction (https refused, non-loopback http with credentials refused unless `allow_insecure_upstream`, limits non-zero, a stdio config requires a `LaunchPolicy` decision).

## 4. Tests (binding)

* **No sockets, no child processes** in the tests you run (your sandbox cannot run them): stdio over `tokio::io::duplex`, HTTP through the in-memory `HttpPost` fake, time through `tokio::time::pause`; tests that need a socket or a child are `#[ignore = "needs loopback sockets"]` / `#[ignore = "needs child processes"]` and the reviewer runs them.
* **Wire fixtures from the pinned specs**: for each of `server/discover`, `tools/list` (paginated, 3 pages), `tools/call` (structuredContent, JSON text, plain text, `isError`), `resources/list`, `resources/read`, `initialize` (legacy): take the example/response shapes from the cited files of `third_party/specs/` and run them through the decoder; table of required fields (`resultType`, `ttlMs`, `cacheScope`) present/absent/malformed per era.
* **Era negotiation**: modern server (stdio and HTTP), legacy-only server (answers `-32601`/HTTP 400 `-32022` to the probe), a server that lies about its version, session id echo and `404` re-initialise (once, not in a loop), `DELETE` on close.
* **Mapping**: golden `Describe` for a fixture server with 6 tools (annotations present and conflicting: `readOnlyHint: true` on a tool an admin classified as mutation stays a mutation; `destructiveHint` never relaxes anything), name sanitising and collision table, SDL parses with `gap_ql` and has no reserved name, hostile tool lists (10,000 tools, a 1 MiB description, deeply nested `inputSchema`, duplicate names, `__` names) end bounded.
* **Calls**: result mapping table, `input_required` result -> the documented error, sampling/roots request from the server -> refused and no call to any model path, per-call timeout and deadline (request never sent when past), cancel mid-call (stdio sends `notifications/cancelled` with the right `requestId`; modern HTTP drops the stream and sends nothing; legacy HTTP both), `max_in_flight` saturation, oversized frame, EOF mid-call fails pending calls, id reuse never mixes two replies (proptest over interleavings), `foreach` (`upstream_calls`, concurrency never above the cap, failing key isolated, duplicates evaluated once).
* **Launch policy**: `Refuse` always errors; an allow-list entry with a wrong sha256, a relative path, a missing file, a symlink to another file: refused before any `exec`; the environment is cleared (assert on the `Command` description you build, no spawn needed).
* **Secrets**: a canary bearer/launch argument never appears in `Debug`, errors, logs, `Describe`, `Complete`.
* **NGC kit**: `crates/gap-conformance/tests/ngc_kit_mcp.rs` serves `McpConnector` over a fake MCP server with `in_memory_grpc` and runs `ngc_kit::run_kit` with `conformance/ngc/mcp.kit.toml` (profile: a keyed read tool for `[read]`, a paginated list tool for `[page]`, a tool that never answers for `[slow]`, a tool whose answer exceeds the response cap for `[size]`): `report.compatible()`, no `NotCovered`; one `#[ignore]` variant over real TCP gRPC and an HTTP loopback MCP stub.
* Every test carries `// spec: <ID>` (CMP-010..015, NGC-010, 020, 025, 026, 027, 060, 061, 090, 091, INV-12, INV-15, INV-18) and the traceability tool stays green; deterministic, 3 runs without flakiness.

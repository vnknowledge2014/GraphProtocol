## 3. Design (binding shape; names inside a module are yours unless stated)

1. **`config`**: `TransportConfig { profile: Profile::{Dev, Prod}, limits: gap_core::config::LimitsConfig, max_deadline: Duration (default 60 s), default_deadline: Duration (30 s), exec: ExecLimits, api_keys: Vec<ApiKeyRecord { id, blake3_hex, tenant, scopes }>, draining: Arc<AtomicBool> }`; validation at construction; `Debug` redacts key material.
2. **`app`**: `fn router(state: Arc<AppState>) -> axum::Router` with `AppState { snapshot: Arc<SnapshotHandle>, registry: Arc<ConnectorRegistry>, plan_cache: Arc<PlanCache>, config, metrics, clock }`. Routes: `POST /graphql` (and `/graphql/stream` as the SSE alias), `GET /graphql` (persisted operations only), `GET /healthz`, `GET /readyz`, `GET /metrics`; everything else `404`, wrong methods `405` with `Allow`.
3. **Pipeline** (spec/01 §5.1) as a `tower` stack `TransportMux -> Gateway -> Operation -> Authz -> Plan -> Exec`, each layer a `tower::Service`/`Layer` with its own typed request (RUN-001), cancel-safe, one `tracing` span per layer with the OPS-010 names (`gap.request`, `gap.gateway.authn`, `gap.operation.validate`, `gap.authz`, `gap.plan`, `gap.exec`, `gap.assemble`) and the attributes of the table (`gap.generation`, `gap.operation_name`, `gap.plan_cache`, `gap.plan_hash`, `gap.partial`; never secrets or raw queries: hash them, OPS-011).
   The snapshot is pinned **once** per request after authentication (INV-01) and travels in the request context; `plan` goes through `PlanCache::get_or_plan`; `exec` gets `deadline = now + min(client deadlineMs, max_deadline)` (RUN-030; read the client value from `extensions.gap.deadlineMs` of the body, absent = default) and a `CancellationToken` that is cancelled when the HTTP request future is dropped (client disconnect).
4. **`gateway`**: request id (`X-Request-Id` accepted if it is a UUID or `[A-Za-z0-9-]{1,64}`, otherwise minted UUIDv7; echoed in the response header and in `extensions.gap`... only `correlationId` of errors), body size cap from `limits.max_request_body_bytes` enforced while reading (stop at the cap, `413`), content-type check (`application/json` only on POST, else `415`), JSON depth bound, `gap_ql::check_variable_map_size`, request timeout.
   Authn: `dev` profile: no credentials = anonymous principal (scopes `read`), valid API key = that key's principal; `prod`: credentials required (`401` + `WWW-Authenticate: Bearer` otherwise). API keys come as `Authorization: Bearer <key>` or `X-API-Key`; the key is hashed (blake3) and compared in constant time against the records (`ApiKeyVerifier` trait); a wrong key is `401` in both profiles. **Tenant and principal come only from authentication** (SEC-010): `X-Tenant` and body fields are ignored (test it).
5. **`operation`**: parse + validate with `gap_ql` against `snapshot.schema` (persisted GET resolved through `gap_ql::persisted`), the cost check is the planner's. Response media type by `Accept`: `application/graphql-response+json` (default when `*/*` or absent... follow the pinned text), `application/json` fallback with the legacy status rules, `text/event-stream` -> SSE; unacceptable `Accept` -> `406`.
   Status mapping per spec/02 §10: JSON/GraphQL parse failure `400`, validation/coercion/operation resolution `422` (no `data`), `GAP_UNAUTHENTICATED` `401`, `GAP_FORBIDDEN` `403`, `GAP_RATE_LIMITED` `429` + `Retry-After`, `GAP_OVERLOADED` `503` + `Retry-After`, `GAP_RESPONSE_TOO_LARGE` per the spec text, everything produced during execution is `200` with `errors[]` and `extensions.gap.{generation,cost,partial}` (GQL-050/051).
6. **`health`**: `/healthz` = `200 {"status":"ok"}` while the process answers; `/readyz` = `200` only when a snapshot is loaded and the server is not draining and at least one branch of `registry` is registered (else `503` with the failing conditions listed); `/metrics` = Prometheus text exposition (hand-written, deterministic order): `gap_http_requests_total{route,status}`, `gap_http_in_flight`, `gap_http_request_duration_seconds` histogram (fixed buckets), `gap_plan_cache_total{result}`, `gap_snapshot_generation`; label values come from a closed set (no user input: INV-15, bounded cardinality).
7. **SSE plumbing** (`graphql-sse` distinct-connections mode): `Accept: text/event-stream` on `/graphql` or `/graphql/stream` returns `event: next` with the execution result, then `event: complete`; request errors (parse, validation) are reported **inside** the stream as a `next` event carrying `errors` (pinned text: not an HTTP 4xx); the event channel is a bounded `tokio::sync::mpsc` (capacity configurable, default 16), a slow client never grows memory, dropping the connection cancels the execution.
8. Crate header as the other crates; the existing placeholder modules (`ratelimit`, `shed`) stay.

## 4. Tests (binding)

* **No sockets, no child processes**: drive the router with `tower::ServiceExt::oneshot`; end to end with the real `gap_snapshot::compose` snapshot (build it from two branch descriptions), the real planner and executor and branches served by `gap_ngc_sdk` mocks through `in_memory_grpc` (paused time). One `#[ignore = "needs loopback sockets"]` smoke test serves the router with `axum::serve` on `127.0.0.1:0` and talks to it with `reqwest`-less raw HTTP over `tokio::net::TcpStream` (the reviewer runs it).
* Status matrix: one test per row of the mapping in section 3.5 (400, 422, 401, 403, 413, 415, 405, 406, 404, 429, 503, 200 with partial errors), each asserting status, media type, absence of `data` on request errors, `extensions.code`, `Retry-After`; `application/json` fallback variant of the same.
* Gateway: request id echo/mint/reject, body cap enforced while reading (a body larger than the cap is not buffered: count the bytes read), deep JSON, huge variables, wrong content type, API key good/bad/missing in `dev` and `prod`, constant-time verifier (no early exit: test the implementation, not timing), `X-Tenant` ignored, secrets never in logs or errors (canary in the key).
* Pinned snapshot: a request that started on generation 1 is answered from generation 1 although generation 2 is published mid-flight (INV-01; compare data content); `extensions.gap.generation` equals the pinned one; plan cache hit/miss visible in `/metrics` and in the span attribute.
* Deadline: client `deadlineMs` capped by `max_deadline`; the connector sees the deadline (RUN-030); dropping the request future cancels the connector call within 50 ms (paused time, the mock's drop guard).
* `/healthz`, `/readyz` (each failing condition), `/metrics` golden text; SSE: success, error-inside-stream, bounded channel with a slow consumer (the producer waits or drops per your documented choice, memory bounded), client drop cancels execution.
* Spans: with `gap_testkit::tracing_capture` assert the OPS-010 span names and attributes for one request and that no attribute contains the raw query or the key canary.
* Every test carries `// spec: <ID>` (GQL-003, GQL-050, GQL-051, OPS-002, OPS-010, OPS-011, RUN-001, RUN-002, RUN-030, SEC-010, INV-01, INV-02, INV-15); deterministic, 3 runs without flakiness.

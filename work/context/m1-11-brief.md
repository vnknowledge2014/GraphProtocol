## 3. Design (binding shape; names inside a module are yours unless stated)

Crate header as the other crates (`#![forbid(unsafe_code)]`, the clippy denies already in `lib.rs`; tests may use `expect`). Modules:

1. `document` — parse an OpenAPI 3.0/3.1 JSON document (`serde_json`) under `ExtractLimits { max_bytes 8 MiB, max_depth 64, max_items, max_ref_hops 32 }`. A malformed or hostile document returns `Err(ExtractError)` quickly, never panics, never allocates without bound (deep nesting,
   `$ref` cycles and chains, huge arrays, a 50 MiB string). `$ref` is resolved locally (`#/...` JSON pointer, with `~0`/`~1` unescaping); any other form is rejected. `servers[]` is recorded in the report and never used.
2. `extract` — `Document -> Extraction { operations, report }`. One operation per `path × GET`. Name = `operationId` sanitised to `[A-Za-z_][A-Za-z0-9_]*`, else `get_<segments>`; collisions are made unique deterministically (suffix `_2`, `_3`, ...). Same bytes give the same `Extraction`
   (ING-010: sorted, no `HashMap` iteration order leaking out). An operation with an unsupported feature (cookie parameter, `deepObject`, a parameter the connector must not set, see 4) is skipped with a reason in `report.skipped`.
   Pagination is detected narrowly: query parameters named exactly `limit` and `offset` (`PaginationKind` offset-style on the descriptor, cursor on the wire); ordering: a query parameter named exactly `sort` (`sort=<field>` ascending, `sort=-<field>` descending) sets `capabilities.order_by`.
   The key fields of an operation are the path parameters of a keyed read. `predicate_ops` stays empty in v0; a `predicate` in a request is `INVALID_ARGUMENT` (NGC-023).
3. `schema` — JSON Schema 2020-12 for `input_schema`/`output_schema` (local refs only, copied from the document with the `$ref`s inlined or rewritten to `#/$defs/...`, bounded) and the SDL: object types from response schemas, enums, scalars `String/Int/Float/Boolean/ID`, a branch-local `scalar JSON` for what cannot be typed
   (`oneOf`/`anyOf`, free-form objects), and one root field per operation. The SDL must pass `gap_ql::schema::with_gap_builtins` (the kit's `describe.valid`); names never start with `__` and never use a GAP reserved name (GQL-004). `spec_hash` = hex of `blake3(document bytes)`; `Describe(known_spec_hash)` answers `not_modified` for it (NGC-010).
   Descriptor `annotations` (untrusted hints): `batch` = `native` or `emulated`, `openapi.method`, `openapi.path`, `openapi.operation_id`. `side_effect_hint` is `NONE` and `idempotent_hint` true for every `GET`.
4. `request` — the request builder (CMP-030). Input: the operation template and the validated arguments. Output: a relative path-and-query, a header list and nothing else; scheme and host come only from `OpenApiConfig::base_url`.
   * Path parameter values are percent-encoded with only RFC 3986 unreserved characters left alone, and the values `.` and `..` are encoded too (`%2E`), so no value can add a segment, a query, a fragment or a dot-segment.
   * Query: names and values percent-encoded; `form` style with `explode` true/false for scalars and arrays; objects are unsupported (the operation is skipped at extraction).
   * Header parameters: the name must be an RFC 7230 token, the value must not contain control characters (CR, LF, NUL: reject the call with `INVALID_ARGUMENT`); parameters named `Accept`, `Content-Type`, `Authorization` are ignored as OpenAPI says; `Host`, `Content-Length`, `Transfer-Encoding`, `Connection`, `Cookie` make the operation skipped.
   * Arguments are validated against the operation's input schema before anything is sent (`INVALID_ARGUMENT`, NGC-060): a small internal validator for the keywords the generated schemas use (`type`, `enum`, `required`, `properties`, `additionalProperties: false`, `items`, `minimum/maximum`, `minLength/maxLength`, `pattern` via `regex`); unknown keywords are ignored. Unknown arguments are rejected.
5. `auth` — `OpenApiConfig::auth` is `None`, `Bearer { credential }`, `ApiKey { location: Header|Query, name, credential }` or `Basic { user, credential }`, where `credential` is a reference resolved through `trait CredentialSource` (a static map for tests). The secret appears only on the wire to `base_url`: never in `Debug` (redact), logs, errors, `Describe`
   or `Complete`. Credentials are sent only over `http` to a loopback host unless `allow_insecure_upstream = true`; otherwise building the connector fails. `https` base URLs are refused (no TLS backend).
6. `upstream` — `trait Upstream: Send + Sync + 'static` with `fn send(&self, UpstreamRequest) -> impl Future<Output = Result<UpstreamResponse, UpstreamError>> + Send` (request: method fixed to `GET`, relative path-and-query, headers, timeout; response: status, headers, body bytes already capped).
   `HttpUpstream` (reqwest) enforces the body cap while reading (`chunk()` loop and an early check of `Content-Length`; over the cap is `UPSTREAM_ERROR` and the rest of the body is never read) and `Content-Type` JSON only (`application/json` or `+json`; anything else is `UPSTREAM_ERROR` unless `allow_binary`, then `{ "raw": <base64> }`: hand-rolled base64, no new crate). `FixtureService` (see 8) also implements `Upstream`.
   The connector is generic over `U: Upstream` (no `dyn`, like the SDK).
7. `connector` — `OpenApiConnector<U>` implements `gap_ngc_sdk::Connector`: `describe`, `query` (solo, paged, foreach), `health`; the other RPCs keep the SDK's `UNIMPLEMENTED` defaults and the capabilities do not advertise them.
   * Error mapping (NGC-060/061; document the table in the crate docs and test every row): upstream 404 on a keyed read gives zero rows, not an error (solo and foreach alike); 400/422 `INVALID_ARGUMENT`; 401/403 `UPSTREAM_ERROR` with a fixed message (the connector's credential was rejected: say nothing else, never the upstream body); 429/503 `UNAVAILABLE` (retryable, with `retry_after_ms`); other 5xx `UPSTREAM_ERROR`
     (retryable); 3xx `UPSTREAM_ERROR`; timeouts follow the deadline (`DEADLINE_EXCEEDED`). Upstream bodies and URLs never reach error text.
   * Retries (CMP-033): `GET` only, at most 2 retries, on connect failures, 429 and 503. The delay is `Retry-After` (delta-seconds or HTTP-date, `httpdate` is vendored but not a dependency: parse delta-seconds only and treat a date as 1 s), capped by `max_retry_delay`; if the delay does not fit before the call's deadline the call fails at once with `retry_after_ms` instead of sleeping. Sleeping uses `tokio::time` so tests run on paused time.
     Every attempt counts in `upstream_calls`.
   * Time: deadline and cancellation come from `CallScope`; the per-request timeout is `min(config.request_timeout, remaining deadline)`. Dropping the future at any await point must leave no work behind (NGC-090).
   * Pagination (NGC-021/022): the cursor is opaque, `hex(json{v, operation, args_hash, tenant, offset})`, bound to (operation, `blake3` of the canonical arguments, tenant); a cursor of another operation, other arguments, another tenant or garbage is `INVALID_ARGUMENT`. Order is the operation's `sort` when asked, else upstream order, and the next page continues at the offset after the last row actually returned.
   * Size (NGC-027): rows are cut when the serialised answer would pass `limits.max_response_bytes` (configurable, default 4 MiB), `Complete.truncated = true`, and `next_cursor` is set when the operation is paginated. The hard cap of `HttpUpstream` is separate and larger.
   * `foreach` (CMP-032, NGC-020/026): use `gap_ngc_sdk::foreach`. Native: a keyed read whose operation carries the extension `x-gap-in-param` = `{ "path": "/customers", "param": "ids", "key_field": "id", "max_batch_size": 50 }` (`path` is a `GET` path of the same document, `param` a list-valued query parameter sent as `ids=1,2,3`, `key_field` the response field that carries the key). One upstream
     call per chunk of at most `max_batch_size` distinct keys; rows are regrouped by `key_field`; a key without a row gives an empty index. Without the extension: bounded fan-out (`config.fanout_concurrency`, default 8) with one upstream call per distinct key and `annotations["batch"] = "emulated"`. `Describe.limits.max_batch_size` is `max_batch_size` (native) or `config.emulated_batch_limit` (default 100, at least 1).
     `Complete.upstream_calls` is the number of upstream requests actually made, retries included. A failing key is isolated to its own closing chunk.
   * `health` (NGC-070/072): `SERVING` once a document is loaded; `details.capacity_weight` from the latest `X-RateLimit-Remaining` / `X-RateLimit-Limit` pair, clamped to (0, 1], 1.0 when absent or invalid.
8. `fixture` — `FixtureService`: a deterministic, in-memory REST service with three resources plus two control endpoints, driven by `tests/fixtures/openapi/shop.openapi.json` (the document the connector is tested against; keep it in sync, a test asserts the fixture serves exactly the paths of the document):
   `customers` (`GET /customers/{id}`, `GET /customers?limit&offset&sort&region&ids=` with 12 rows, `ids` is the native batch of the keyed read), `orders` (`GET /orders/{id}`, `GET /orders` with `limit`/`offset`; no extension, so foreach is emulated), `products` (`GET /products/{sku}` where `sku` is a string that may contain `/`-like and `..` content: hostile-value tests),
   `GET /blobs` (40 rows of about 1 KiB, paginated: the NGC-027 probe) and `GET /slow` (never answers until the caller drops the request: the NGC-025 probe). Every response carries `X-RateLimit-Limit` and `X-RateLimit-Remaining`; the service can be told to answer `429`/`503` with `Retry-After` for the next n requests, to count requests, to record the received path and headers
   (so tests can assert what was sent and that no credential leaked), and to hold a high-water mark of concurrent requests. All of it is plain Rust: `async fn handle(&self, UpstreamRequest) -> UpstreamResponse`, no sockets. `fixture::router(Arc<FixtureService>) -> axum::Router` is a thin wrapper for real sockets (used by the walking skeleton and by the reviewer's smoke test).

## 4. Tests (binding)

* **No sockets, no child processes** in the tests you run: your sandbox cannot run them (tests that need a loopback socket are marked `#[ignore = "needs loopback sockets"]` and the reviewer runs them with `--ignored`; one of them runs `HttpUpstream` against `fixture::router` on `127.0.0.1:0`). Everything else uses `FixtureService` as the `Upstream`, `tokio::time::pause`, and the SDK's
  `in_memory_grpc` for the gRPC path.
* **NGC kit**: `crates/gap-conformance/tests/ngc_kit_openapi.rs` builds `OpenApiConnector<FixtureService>`, serves it with `in_memory_grpc`, loads `conformance/ngc/openapi.kit.toml` (`Profile`) and runs `ngc_kit::run_kit`; it asserts `report.compatible()` and that no check is `NotCovered`. Mutation, idempotency and dry-run are not advertised, so those checks are `NotApplicable`. The profile uses `customers` for `[read]`/`[page]`, `GET /slow` for `[slow]`, `GET /blobs` for `[size]`.
* **Extraction**: golden `Extraction` for `shop.openapi.json` (names, key fields, pagination/sort detection, annotations, skipped list, byte-identical on a second run); name sanitising and collision table; `$ref` table (local ok, `#/a~1b` unescaped, external/remote/`file:` rejected, cycle rejected, chain over `max_ref_hops` rejected); `servers[]` recorded and never used; hostile corpus under
  `tests/fixtures/openapi/hostile/` (deep nesting, wide object, long `$ref` chain, 10 MiB document, huge enum, cyclic schema, `servers` with an internal host) each ending in a bounded `Err` or a bounded `Ok`, plus a proptest over random JSON bytes that never panics.
* **SDL/schema**: the SDL of the shop document parses with `gap_ql` and has no reserved name; `describe` twice is equal; `known_spec_hash` gives `not_modified`; input schemas validate good arguments and reject each bad class (wrong type, missing required, unknown argument, over `maxLength`, `pattern`).
* **Request builder** (property tests over arbitrary strings, including `/`, `..`, `%2e`, `?`, `#`, `\r\n`, NUL, unicode, 4 KiB values): the produced path has exactly the template's segment count, no `..` segment, no raw `?` or `#` from a value; the query has exactly the declared parameters; no header value contains CR/LF/NUL; scheme and host are untouched. Against `FixtureService`, assert on the *recorded* request, not on your own builder.
* **Auth**: bearer, api-key header, api-key query, basic reach the upstream exactly once and only to `base_url`; the secret is absent from `Debug`, logs (`tracing_capture` from `gap-testkit` if you use it, else a test subscriber), errors, `Describe` and `Complete`; non-loopback `http` with credentials is refused unless `allow_insecure_upstream`; `https` refused.
* **Connector**: error-mapping table (every row), retry table (429, 503, connect error: retried; 400, 404, 500: not; `Retry-After` honoured; delay beyond the deadline fails at once without sleeping; at most 2 retries; `upstream_calls` counts attempts), 3xx not followed, over-cap body, wrong content type, `allow_binary`,
  cursor round trip and each cursor rejection, truncation and resume drain every row exactly once, native foreach (`upstream_calls == ceil(distinct / max_batch_size)`, duplicates evaluated once, absent key empty, failing key isolated), emulated foreach (`upstream_calls == distinct keys`, concurrency never above `fanout_concurrency`), deadline already past (upstream never called), deadline mid-call and cancel
  (the request future is dropped; `FixtureService` shows no request left running), `health` capacity weight table (including garbage and out-of-range headers).
* Every test carries `// spec: <ID>` (CMP-030..033, NGC-020, 021, 022, 025, 026, 027, 060, 072, 091, INV-15, INV-18) and the traceability tool stays green. Deterministic: no wall-clock sleeps, 3 runs without flakiness.

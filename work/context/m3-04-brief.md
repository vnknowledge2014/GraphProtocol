## 3. Design (binding shape)

1. **Time.** The registry owns an `Arc<dyn Clock>` (`ConnectorRegistryBuilder::with_clock`, default `SystemClock`) and an epoch `Instant`; `Now::from_ms(clock.now_instant() - epoch)` is computed once per `open_query` and passed by value into every `gap-balance` call. Tests use `ManualClock`.
2. **Replicas.** `RegisteredBranch` holds one or more `Replica { client, bulkhead (non-queueing, max_in_flight), slot: Arc<TelemetrySlot>, tiebreak uid, metadata }`; `ConnectorRegistryBuilder::register_replicas(uid, label, default_timeout_ms, Vec<ReplicaSpec>)` is new, the existing `register`/`register_with_metadata`/`register_branch` keep their signatures and create one replica (`label` = the branch id when a descriptor is given, otherwise the uid string; labels are tenant-free, 1..=64 bytes, control characters replaced). `max_in_flight()`/`available_permits()`/`client()` keep answering for replica 0 / the sum where documented.
3. **`open_query(uid, request, scope)`** (signature unchanged), per call: `now`; `slot.on_first_attempt()` of the first chosen replica (deposit, RTE-091); loop for attempt `0..=max_retries` (default 2, RTE-090):
   a. candidates = replicas not excluded whose breaker is not `Open` (RTE-073); none left -> `GAP_BRANCH_UNAVAILABLE` with `retry.afterMs` = the smallest remaining open time (RTE-081; if the only reason is saturated bulkheads -> `GAP_OVERLOADED` as today);
   b. pick with `p2c::select_excluding` and a thread-local `XorShift64` (or the seeded one injected for tests: `ConnectorRegistryBuilder::with_rng_seed`), never a global argmax (RTE-074, RTE-079);
   c. `breaker.admit(now)`: `Rejected` -> exclude, try the next; `Probe(permit)` -> keep the permit for the call; non-queueing `try_acquire` of the bulkhead (saturated -> exclude and try another, else `GAP_OVERLOADED`); `InFlightGuard::acquire(&slot)`;
   d. call `client.query(request.clone(), scope.clone())` (merge branch metadata as today, never override caller metadata, redact in `Debug`, INV-15). On `Err(e)`: classify (`INVALID_ARGUMENT`, `PERMISSION_DENIED`, `NOT_FOUND` -> `Outcome::ClientError`; everything else, timeouts included -> `Failure`), record exactly once (`ProbePermit::record` when probing, else `slot.record`), then retry **only if** the error is `retryable`, `attempt < max_retries`, `retry_budget().try_withdraw()` succeeds and the jittered backoff `min(50 ms * 2^attempt, 1 s)` (full jitter from the same RNG) still ends before `scope.deadline - margin`; the retry excludes the replica that failed (so with replicas it goes to a different one); otherwise return `BranchQueryError::Connector(e)`.
   e. `Ok(stream)`: wrap it (permit, in-flight guard, probe permit travel with the stream as the bulkhead permit does today) so the call is accounted **exactly once** at its end: a completed stream (`Complete` chunk) -> `Ok` with the elapsed latency; a stream error -> `Failure`/`ClientError` by the same classification; dropped before the end (client cancel, deadline) -> **no record** and the probe permit is released without an outcome (RTE-085: cancelled callers cannot stall an episode). Retries cover errors that arrive while opening the call, never rows already delivered.
   f. every sleep honours `scope.cancel` and the deadline (cancel within 50 ms, RUN-031).
4. **Health polling** (`BranchClient::health` is added with a default `Ok(Serving)` implementation so existing clients and fakes keep working; implement it for `GrpcClient` and `InProcess<C>` via their `Health` RPC): `ConnectorRegistry::spawn_health_pollers(cancel: CancellationToken) -> HealthPollers` starts one task per replica; every 5 s with +-20% jitter it calls `health` bounded by 500 ms (NGC-070) and feeds `slot.apply_health(status, capacity_weight from details.capacity_weight, now)`; a failed or timed-out poll counts as `NOT_SERVING` (RTE-083: immediate `Open`; recovery goes through the breaker's probes). Dropping `HealthPollers` or cancelling the token stops the tasks (no leak, tested). The interval and jitter are `ResilienceConfig` fields (tests use milliseconds under paused time).
5. **Stats for metrics**: `ConnectorRegistry::branch_stats() -> Vec<BranchStats>` (label, per replica: breaker state, in-flight, capacity, latency EWMA, error rate, retry-budget balance, monotonic counters `calls_ok`, `calls_failed`, `calls_client_error`, `retries`, `breaker_rejections`, `bulkhead_rejections`, `health_failures`), sorted deterministically, allocation only on this cold path. The Prometheus names of the follow-up are `gap_branch_in_flight`, `gap_branch_calls_total{branch,outcome}`, `gap_breaker_state{branch}` (0 closed, 1 half-open, 2 open), `gap_retry_total{branch}`, `gap_branch_capacity`; label values come only from the tenant-free branch label (INV-15, bounded cardinality).
6. `ResilienceConfig { max_retries: 2, backoff_base: 50 ms, backoff_cap: 1 s, health_interval: 5 s, health_jitter: 0.2, health_timeout: 500 ms }` with validation; `Default` = the spec values.
7. Crate docs: one section on the call accounting rule (exactly once, drops are not outcomes) and one on why retries never replay delivered rows.

## 4. Tests (binding; `connector_layer` in every test name: acceptance filter `test(connector_layer)`)

* Single replica: breaker opens after 20 calls with >= 50% failures (`GAP_BRANCH_UNAVAILABLE` with `afterMs` decreasing with the clock), half-open probes (3 probes, majority) close or re-open it, cancelled callers release the probe slot, client errors never open it, slow calls count (RTE-080/084/085).
* Retries: `QUERY` with a retryable error is retried at most twice with the jittered backoff (assert the sleep lengths with a seeded RNG), never beyond the deadline, never for a non-retryable code, never once the budget is empty (RTE-091: 11 concurrent withdrawals against 10 tokens succeed 10 times), deposits 0.1 per first attempt, a retry goes to another replica, rows already delivered are never replayed.
* Replicas: P2C spreads load (herding test: no replica share swings by more than 20% when one slows down), a replica whose breaker is open is skipped, all open -> `GAP_BRANCH_UNAVAILABLE`, bulkheads stay non-queueing, replica-addition invariance of single-replica behaviour.
* Health: `DEGRADED` halves capacity (RTE-086), `capacity_weight` scales it, out-of-range weight is treated as 1.0, `NOT_SERVING` opens the breaker at once, a failing/hanging health RPC counts as `NOT_SERVING`, jitter stays within +-20%, pollers stop on drop/cancel.
* Accounting: 10,000 cancelled calls leave `in_flight == 0` (RTE-071) and no outcome recorded; every completed call is recorded exactly once (count `calls_*` against the number of calls).
* Metrics: `branch_stats` values after a scripted scenario, deterministic order, labels free of tenant data.
* Existing `WP-M1-07` tests and `cargo test -p gap-exec` stay green; no `unwrap`/`expect`/`panic` outside tests; `// spec: <ID>` markers name spec ids only (RTE-*, NGC-070..072, RUN-030..032, INV-02, INV-12, INV-15).

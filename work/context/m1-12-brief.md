## 3. Design (binding shape; names inside a module are yours unless stated)

1. **`gap.toml`** is **one** document modelled by `gap_core::config::GapConfig`, which the reviewer already extended (read `crates/gap-core/src/config/branches.rs` and `docs/config.schema.json`): the core tables plus `[[branches]]` (`BranchSpec`: `id`, `protocol = "openapi" | "mcp"`, `trust`, optional `uid`, `[branches.openapi]` or `[branches.mcp]` with `auth` as a `SecretRef`) and `[[api_keys]]` (`ApiKeySpec`: `id`, `key_hash` = blake3 hex, `tenant`, `scopes`).
   Validation (`GapConfig::validate`) already names the failing key path (`ConfigError::InvalidEntry { path, reason }`) and never echoes a secret. **You do not change `gap-core` or `docs/`**; if the model is missing something, stop and ask. Use `GapConfig::load_from_path_with_process_env` (so `GAP_*` overrides keep working for the scalar keys).
   `branch uid` = `uid` when configured, otherwise a deterministic UUIDv7-shaped id derived from the branch `id` (blake3, version/variant bits set) so snapshots are reproducible. The OpenAPI document path is relative to the directory of `gap.toml`.
2. **`assemble`** (`gap_server::assemble::{ServerFile, Assembled, BranchRuntime, BranchFactory, assemble}`): turns a `ServerFile` into `Assembled { app_state: Arc<AppState>, snapshot_handle, facade: McpFacade, engine: TransportEngine, ... }`. A `BranchFactory` trait (object-safe, async) builds one `BranchRuntime { client: Arc<dyn BranchClient>, description: ConnectorDescription, handle: <whatever keeps the connector alive> }` per branch spec; the production factory builds `OpenApiConnector` / `McpConnector`, wraps it in `ServerCore` and `in_memory_grpc` (embedded mode, OPS-003 c), calls `Describe` and returns the pieces; tests inject fakes (`gap_ngc_openapi::Upstream`, `gap_mcp::outbound::fake::FakeMcpServer`) through the same trait. Then: `compose` all branches (a composition error is a startup error with the branch id and code, never a panic), `SnapshotBuilder` -> `SnapshotHandle`, `ConnectorRegistry::builder().register(uid, client, limits.max_in_flight)`, `AppState` (`TransportConfig` derived from `GapConfig`: profile, limits, deadlines, `api_keys`, the shared `draining` flag), `.with_http_module(McpFacade)` where the facade uses `HideT2` in `prod` and `AllVisible` in `dev`, `spotlight` from `[gateway].facade_spotlight`, `TransportEngine` as its `GraphqlEngine`.
   A branch that fails `Describe` at startup is a startup error in `prod` and a warning + `GAP_BRANCH_UNAVAILABLE` registry entry-less skip in `dev`? **No**: keep it simple and deterministic: any branch failure is a startup error naming the branch (a later WP adds degraded startup).
3. **`run`** (`gap_server::run::{serve_http, serve_stdio, Shutdown}`): `serve_http(assembled, listener)` = `gap_transport::serve(listener, router(state), shutdown, ServeOptions{ header_read_timeout, max_connections, shutdown_grace = [server].shutdown_grace_ms })`; `Shutdown` turns SIGTERM and SIGINT into the shutdown future: the **first** signal sets `TransportConfig::draining` (so `/readyz` answers `503` at once) and then completes the future; a **second** signal exits the process with a non-zero code immediately (RUN-090). `serve_stdio` mounts the same facade on `StdioServer` over stdin/stdout with a `ContextFactory` that builds a `Service` principal with the scopes of `[auth]` (SEC-004), pins a fresh snapshot per request and applies `[limits]`; stdout carries protocol frames only, logs go to stderr.
   Logging: `tracing-subscriber` initialised once from `[telemetry]` (`log_json`, level) to **stderr**; no secrets or raw queries in log fields (OPS-011).
4. **`gap` CLI** (`gap-cli`, clap derive, `gap --help` lists every OPS-044 command; commands owned by later WPs print a one-line "not available in this build (WP-...)" and exit 2):
   * `gap serve [--config gap.toml] [--stdio]`: load, assemble, serve; exit codes: 0 clean shutdown, 1 runtime failure, 2 usage/config error.
   * `gap init [DIR] [--force]`: writes `gap.toml` and the walking-skeleton example files (REST fixture + OpenAPI document + MCP fixture) into `DIR` (refuses to overwrite without `--force`, never writes outside `DIR`, never follows a symlink out).
   * `gap doctor [--config gap.toml]`: checks the config parses, every referenced file exists and is readable, the listen address is parseable and (without binding) not a wildcard in `prod`, `prod` has at least one API key, T2 branches are flagged, stdio MCP commands are absolute paths with a pinned hash; each check prints `ok`/`warn`/`fail` with the fix; exit 0 only without `fail`. Toolchain/sandbox/model checks are listed as `skipped (not available in M1)`.
   * `gap config schema`: prints `GapConfig::json_schema_pretty()` (core + `branches` + `api_keys`; must equal `docs/config.schema.json`); `gap config check FILE`: parses and validates without starting anything (the acceptance command).
5. **`examples/walking-skeleton`**: `README.md` (end-to-end, copy-paste, expected output of each step), `gap.toml` (dev profile, an OpenAPI `shop` branch over a REST fixture and an MCP `notes` branch over an HTTP MCP fixture, one API key), `shop.openapi.json` (OpenAPI 3.0 with `customers` list/get and `orders`, `x-gap-in-param` batch where useful), `fixtures/rest_fixture.py` and `fixtures/mcp_fixture.py` (Python 3 standard library only, deterministic data, bind `127.0.0.1`, print the port; the MCP fixture speaks the `2026-07-28` stateless wire with one tool and one resource). Every file is spec-derived or hand-written, never recorded from the running server. `gap config check examples/walking-skeleton/gap.toml` must pass.

## 4. Tests (binding)

* **Config** (the parsing and per-entry validation are tested in `gap-core`; test here what `gap-server` adds): a referenced OpenAPI file that is missing or unreadable is a startup error naming `branches[i].openapi.spec`; the walking-skeleton `gap.toml` loads; environment override of a core key still works; no secret appears in any startup error (canary).
* **Assemble** (no sockets): the walking-skeleton `gap.toml` assembled with fake upstreams; the snapshot has both branches; deterministic uid derivation; composition error and failing `Describe` are startup errors naming the branch; `HideT2` in prod (a T2 branch is invisible through `gap_describe`), `AllVisible` in dev.
* **End to end in-process** (`tower::ServiceExt::oneshot` on `router(state)`): `POST /graphql` answers from both branches (data from the fake REST and fake MCP upstreams, `extensions.gap.generation`); `POST /mcp` with the pinned `2026-07-28` headers runs `server/discover`, `tools/list` (static), `gap_describe{overview:true}`, `gap_search`, `gap_query` (a query across both branches), and a mutation refused by `gap_query`; the API-key path (`Authorization: Bearer` valid/invalid/missing in `prod`); `/healthz`, `/readyz` (flips to `503` when `draining` is set), `/metrics`.
* **Shutdown/signals**: unit-test the `Shutdown` state machine without real signals (inject the signal stream): first signal sets draining then completes, second signal requests a forced exit.
* **CLI**: `gap --help` golden; `config check` pass/fail with exit codes; `config schema` is valid JSON Schema and contains `branches` and `api_keys`; `init` into a temp dir (files, no overwrite without `--force`, symlink escape refused, the generated `gap.toml` passes `config check`); `doctor` on good and broken configs (one test per `fail` check); commands of later WPs exit 2 with one line.

# WP-M1-01 steps — gap-ql: GraphQL-profile front end, built-in schema, limits, cost model, error mapping

- **Assumptions:**
  1. Build and test execution run strictly offline against `.local/vendor` via the existing git-ignored `.cargo/config.toml`. Because `~/.cargo/config.toml` and `~/.config/git/config` sit outside the sandbox, Cargo runs with `CARGO_HOME=.git/tmp-cargo-home __CARGO_TEST_ROOT=/Users/mike/Documents/GraphProtocol` (deleting `.git/tmp-cargo-home` immediately afterwards) and Git runs with `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_SYSTEM=/dev/null` preserving the repository `.git/config` author identity.
  2. Only the approved third-party crates for `WP-M1-01` are declared in `crates/gap-ql/Cargo.toml`: `apollo-compiler`, `serde` (`features = ["derive"]`), `serde_json`, `thiserror`, workspace crate `gap-core` (`L1 -> L0`), and dev-dependency `proptest`. Every entry in `[dependencies]` and `[dev-dependencies]` uses single-line `.workspace = true` / `workspace = true` syntax in alphabetical order so `gap-testkit::workspace_crates_match_layers_and_workspace_deps` (`ARC-001`) and `tools/check_layers.py` (`ARC-002`) continue to pass.
  3. All failures and warnings reuse `gap_core::error::{GapError, ErrorCode, GapResult, Suggestion, PathSegment, SourceLocation}` with `<= 300`-char clamped messages (`GQL-072`, `ADR-023`); `gap-ql` defines no second error enum.
  4. `spec/02-gap-ql.md` §3 (built-in SDL) and §5 (type-system and executable directives) live as verbatim single-source-of-truth files under `crates/gap-ql/schema/*.graphql`, verified at test time against the fenced `graphql` blocks of `../../spec/02-gap-ql.md`. Because `spec/02-gap-ql.md` §4 (`__search`, `__metaGraph`, `SearchResult`, `SearchHit`) uses `__`-prefixed root field names that are intentionally invalid in user-authored SDL (`GQL-004`), §4 is constructed programmatically in `apollo_compiler::Schema` rather than embedded as SDL.
  5. Because `sha2` is not in the `WP-M1-01` crate allowlist, `GQL-061` SHA-256 persisted-operation digests (`extensions.persistedQuery.sha256Hash`) are computed by a small pure-Rust `#![forbid(unsafe_code)]` FIPS 180-4 SHA-256 implementation inside `crates/gap-ql/src/persisted.rs`, verified against NIST FIPS 180-4 test vectors.
  6. `tools/spec_trace.py` validates `// spec: <ID>` comments in `crates/**` exclusively against normative IDs defined in `spec/*.md`. Every test carries `// spec: <SPEC_ID>` (`GQL-001`, `GQL-002`, `GQL-004`, `GQL-010`, `GQL-024`, `GQL-030`, `GQL-031`, `GQL-032`, `GQL-040`, `GQL-041`, `GQL-042`, `GQL-043`, `GQL-060`, `GQL-061`, `GQL-062`, `GQL-070`, `GQL-072`, `INV-06`, `INV-15`) and places ADR references (`ADR-001`, `ADR-023`) in parentheses so `spec_trace.py` reports `0 unknown test IDs`.
- **Rejected simpler alternative:**
  - *Alternative A:* Validate executable documents against the unfiltered supergraph `Schema` and redact diagnostic strings post-hoc with regexes when a hidden field/type/argument is referenced. Rejected because post-hoc string scrubbing is fragile across `apollo-compiler` diagnostic formats (`type mismatch` vs `unknown field` vs `missing argument`) and risks leaking hidden existence via distinct error codes or source locations (`GQL-062`). Projecting a caller-visible `Valid<Schema>` from the `Visibility` predicate before `apollo-compiler` validation and introspection guarantees byte-identical `GapError`s for hidden versus nonexistent elements by construction.
  - *Alternative B:* Duplicate `spec/02-gap-ql.md` §§3 & 5 inline inside Rust string literals without a spec-sync test. Rejected because silent drift between `spec/02-gap-ql.md` and `crates/gap-ql` would break downstream composition (`WP-M1-05`) and conformance (`WP-M1-02`).
- **Risks:**
  1. `apollo-compiler` `1.33.1` rejects `__`-prefixed object field definitions during `Schema::validate()`. Mitigated by validating all SDL + programmatic `SearchResult`/`SearchHit` types via `Schema::validate()` first, then injecting `Query.__search` and `Query.__metaGraph` `FieldDefinition` components onto the validated `Query` object type before wrapping with `Valid::assume_valid`, which makes both `ExecutableDocument::validate` and `introspection::partial_execute` recognize them natively.
  2. `apollo-compiler` `1.33.1` parses `@oneOf` directives but does not enforce `@oneOf` single-field input constraints natively. Mitigated by implementing explicit `@oneOf` schema and executable/coerced-variable checks in `crates/gap-ql/src/validate.rs`.
  3. `cargo-nextest` is not installed in the sandbox and must not be installed. Mitigated by running `cargo test -p gap-ql --locked --offline`, recording acceptance command 1 as `NOT RUN` under Deviations in `work/handoffs/WP-M1-01.md`, and leaving `WP-M1-01` in `doing` status.

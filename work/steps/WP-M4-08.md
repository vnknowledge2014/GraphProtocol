## Steps

1. Design & implement `crates/gap-snapshot/src/publisher/mod.rs` (`RUN-003`, `RUN-004`, `RUN-006`, `INV-16`, `ING-050`, `ADR-009`):
   - `ReclaimerHandle` running on a dedicated background OS thread (`gap-snapshot-reclaimer`) that receives retired `Arc<Snapshot>` values over a bounded channel, waits/polls off the swap & request threads until `Arc::strong_count == 1` (never blocking readers or `SnapshotHandle::pin()`), and drops retired generations cleanly off-thread.
   - `PrewarmQuery` & `PrewarmReport`: re-plans up to top-100 hot query documents (`gap_plan::plan_query`) against the candidate `Snapshot` (or pluggable hook) and validates `>= 95%` pass rate (<= 5% failures), aborting with `PublisherError::PrewarmRegression` unless `PublishOptions::breaking_change_ack` is valid (`RUN-004`, `ADR-009` §6).
   - `ShadowRegistry`: manages staged `shadow:<proposal_id>` candidate snapshots (`ING-050`) isolated from live `SnapshotHandle::pin()` and requires `admin:schema` scope check (`ING-050`).
   - `PublisherActor`: serializes all `publish` and `rollback` transitions behind a single writer / command queue (`RUN-003`), supports bounded coalescing windows (`PublishBatch`), enforces `generation = prev + 1` (`INV-16`), maintains the 5-generation structural-sharing ring buffer (blocking re-promotion of `bad = true` generations unless `force = true` per `ADR-009` §5), and appends structured publish audit records.
   - Unit tests (`test(publisher)`) covering prewarm >= 95% gate, `breaking_change_ack`, coalesced batch publish, off-thread reclaimer waiting on pinned requests (`RUN-006`), shadow staging (`ING-050`), bad-generation lock, and structural-sharing memory efficiency (`RUN-003`, `RUN-004`, `RUN-006`, `INV-16`, `ING-050`).
2. Design & implement `crates/gap-snapshot/src/rollback/mod.rs` (`RUN-007`, `RUN-008`, `INV-16`, `ADR-009` §5):
   - Sliding watch window (default `60 s`) tracking post-promotion calls against a generation baseline:
     - Tracks attributable error rates & `p99` per changed branch (`spec_hash` changed or added), newly activated join edges, planning/validation errors vs unrelated infrastructure errors (`ADR-009` §5: unrelated infra errors must NEVER trigger rollback).
     - Automatic rollback trigger iff attributable error rate `> max(2 * baseline, baseline + 0.02)` with `>= 200` samples (`ADR-009` §5), triggering once per generation.
     - Distinguishes single-branch fault attribution (quarantining only the offending changed branch and preserving other branches in `G+2`), join-edge attribution (disabling/reverting only the faulty join), and unattributed/global planner regression (full rollback to previous clean generation published monotonically as `G+2` with `bad = true` marked on `G+1`, `RUN-007`, `INV-16`).
     - Flap dampening (`RUN-008` / `ADR-009` §5): 3 auto-quarantines within 24h locks the branch into `HardQuarantined` requiring explicit admin acknowledgment to clear.
   - Unit tests (`test(rollback)`) tagged `// spec: RUN-007, RUN-008, INV-16`.
3. Create `tests/swap_stress/swap_stress.rs` and `crates/gap-snapshot/tests/swap_stress.rs` (`RUN-008`, `INV-01`, `INV-02`, `INV-16`, `ADR-009` §3):
   - Concurrent multi-thread / 1,000-task async `swap_stress` over 100 rapid publisher swaps: zero errors, zero torn reads (observed `generation`, schema, ownership, and branch metadata belong consistently to one generation), off-thread reclamation verification, swap latency measurement (`p99 <= 250 us` budget reported/verified), 5-gen structural sharing check, and deterministic state-machine exploration of publisher/reclaimer/rollback invariants.

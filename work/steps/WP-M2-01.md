  3.   4. `tools/spec_trace.py` validates `spec: <ID>` markers in `crates/**` exclusively against requirement IDs defined in `spec/*.md`. Every test carries `// spec: <SPEC_ID>` using `spec/*.md` IDs only and places `ADR-*` citations in parentheses afterwards so `spec_trace.py` reports `0 unknown test IDs`.
- **Rejected simpler alternative:**
  - *Alternative A:* Use a single `Mutex<rusqlite::Connection>` shared by readers and writers or `:memory:` SQLite without WAL. Rejected because readers would block behind an active writer and violate WAL concurrent read guarantees (`m2-01-design.md` §8). File-backed SQLite with `journal_mode=WAL`, one writer `Mutex<Connection>`, and a bounded `SQLITE_OPEN_READ_ONLY` reader pool lets readers run concurrently without `Busy`.
  - *Alternative B:* Build dynamic SQL `IN (?, ?, ...)` lists for `caller.groups`, `caller.task_chain`, `edge_types`, or `scopes`, or pass user query strings raw into `FTS5 MATCH`. Rejected because dynamic SQL breaks the compile-time constant SQL rule (`m2-01-design.md` §3) and raw `FTS5 MATCH` interprets hostile tokens (`"`, `*`, `NEAR(`, `-`, `:`, `OR`) as syntax errors or column filters (`m2-01-design.md` §7). Lists bind as JSON arrays via `json_each(?)` and search queries split into escaped literal tokens.
  - *Alternative C:* Implement `WEIGHTED` or `DFS` with a plain `HashSet<NodeId>` visited set ignoring hop counts under `max_depth`. Rejected because an early longer-hop path at depth `max_depth` would prune a later shorter-hop path that reaches deeper neighbours within `max_depth` (`m2-01-design.md` §6, `ING-067`). Pareto hop-tracking (`[f64; 17]` / `best_depth`) settles every node at its exact minimum cost / preorder without missing `<= max_depth`-hop paths.
- **Risks:**
  1. Opening an existing SQLite file with `READ_WRITE` and running `PRAGMA journal_mode=WAL` before inspecting `PRAGMA user_version` mutates header bytes 18–19 on disk. Mitigated by probing existing files with `SQLITE_OPEN_READ_ONLY` first and returning `StoreError::FormatTooNew` untouched if `user_version > FORMAT_VERSION`.
  2. `serde_json` converts `f64::NAN` and `f64::INFINITY` to `Value::Null` when constructing JSON maps (`json!({"weight": f64::NAN})`). Mitigated in `WEIGHTED` traversal (`ING-067`) by treating an absent `"weight"` key as `1.0`, finite non-negative JSON numbers as valid weights, and any other present `"weight"` value (negative numbers, `null`, `"NaN"`, `"Infinity"`, non-numbers) as invalid weights skipped and counted in `SkippedInvalidWeights`.
  3. `cargo-nextest` is not installed in the sandbox and must not be installed. Mitigated by running `cargo test -p gap-store --locked --offline` (3x) and `--features conformance`, reporting acceptance command 1 as `NOT RUN` under Deviations, and leaving `WP-M2-01` in `doing` state.

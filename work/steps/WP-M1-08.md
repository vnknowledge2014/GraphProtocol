# WP-M1-08 steps — `gap-transport` v0 (`axum` HTTP GraphQL endpoint, `tower` pipeline `TransportMux -> Gateway -> Operation -> Authz -> Plan -> Exec`, health/ready/metrics, and `graphql-sse` plumbing)

- **Assumptions:**
  1. All Cargo commands run strictly offline against `.local/vendor` using `CARGO_HOME=.git/tmp-cargo-home` and `--locked --offline`. Per protocol rules, `.git/tmp-cargo-home` is **left in place** for the reviewer; `cargo nextest` (and `cargo deny`) are not installed in this sandbox and are reported `NOT RUN` in `work/handoffs/WP-M1-08.md`, with 3 consecutive `cargo test -p gap-transport --locked --offline` runs as the deterministic substitute.
  2. `crates/gap-transport/Cargo.toml` and `Cargo.lock` were pre-seeded offline by the reviewer (`axum`, `blake3`, `bytes`, `futures-util`, `gap-balance`, `gap-core`, `gap-exec`, `gap-plan`, `gap-proto`, `gap-ql`, `gap-sec`, `gap-snapshot`, `http-body-util`, `serde`, `serde_json`, `thiserror`, `tokio`, `tokio-util`, `tower`, `tracing`, `uuid`; dev: `gap-ngc-sdk`, `gap-testkit`, `proptest`, `tokio`, `tower`) and require no dependency additions. `tower-http` is not used.
  3. Existing placeholder module declarations `pub mod ratelimit;` and `pub mod shed;` in `crates/gap-transport/src/lib.rs` remain intact for `WP-M3-07`. To exercise `429` (`GAP_RATE_LIMITED` + `Retry-After`) and `503` (`GAP_OVERLOADED` + `Retry-After`) at the HTTP transport layer without modifying `ratelimit`/`shed`, `AppState` exposes an injectable `AdmissionPolicy` trait seam (defaulting to `AllowAllAdmission`).
  4. Per `ADR-023`, `spec/02-gap-ql.md` §10, and `third_party/specs/graphql-over-http/spec/GraphQLOverHTTP.md` (L452–466, L514–586):
     - Execution-phase responses (`200 OK`, including partial errors and execution-aborted `GAP_RESPONSE_TOO_LARGE` with `"data": null`) emit `Content-Type: application/graphql-response+json; charset=utf-8` (or `application/json; charset=utf-8` when `Accept` negotiates the legacy `application/json` fallback) and carry `"extensions": { "gap": { "generation", "cost": { "planned", "actual" }, "partial", "tokensEstimate"? } }` (`GQL-050`, `GQL-051`).
     - Pre-execution GraphQL request errors omit `"data"` (never `"data": null`) and return `400` (`GAP_PARSE_ERROR`, invalid JSON or GraphQL syntax) or `422` (validation, coercion, operation resolution, structural/cost limits, persisted-op errors, unsupported features) with `Content-Type: application/graphql-response+json; charset=utf-8`.
     - Transport/auth errors (`401`, `403`, `404`, `405` + `Allow`, `406`, `413`, `415`, `429` + `Retry-After`, `503` + `Retry-After`) omit `"data"` and use `Content-Type: application/json; charset=utf-8` (never `application/graphql-response+json`).
  5. Per `third_party/specs/graphql-sse-v2.6.3/PROTOCOL.md` (L11–53, distinct-connections mode): when `Accept` negotiates `text/event-stream` on `/graphql` or `/graphql/stream`, valid operations and pre-execution GraphQL parse/validation/unsupported-feature errors alike return `200 OK` `Content-Type: text/event-stream` emitting `event: next\ndata: <json>\n\n` followed by `event: complete\ndata: \n\n` over a bounded `tokio::sync::mpsc::channel(sse_channel_capacity)` (default `16`, producer backpressured via `.send().await` coupled to stream-drop cancellation).
  6. `/readyz` considers a snapshot loaded iff `pinned.generation > 0 && !pinned.branches.is_empty()` (`Snapshot::empty(0)` is the bootstrap unloaded state), server not draining iff `!config.draining.load(Ordering::Acquire)`, and branches registered iff `!registry.is_empty()`.
- **Rejected simpler alternative:**
  - *Alternative A:* Buffer the entire HTTP request body with `axum::body::to_bytes(body, usize::MAX)` and check `bytes.len() <= max_request_body_bytes` afterward. Rejected because `Brief §3.4`, `§4`, and `§5` forbid buffering oversized bodies and require stopping stream consumption immediately upon exceeding `limits.max_request_body_bytes` (`413`). Instead, we read frames incrementally via `http_body_util::BodyExt::frame` and abort as soon as accumulated byte count exceeds the cap.
  - *Alternative B:* Implement the GraphQL endpoint as a single monolithic `axum` handler function. Rejected because `spec/01-architecture.md` §5.1, `RUN-001`, and `Brief §3.3` mandate a typed `tower::Service` / `tower::Layer` stack `TransportMux -> Gateway -> Operation -> Authz -> Plan -> Exec` with per-layer typed requests and `OPS-010` spans.
  - *Alternative C:* Use `tokio::sync::mpsc::unbounded_channel` for SSE event delivery. Rejected because `ARC-011` and `Brief §3.7` forbid unbounded queues; a slow SSE consumer must apply backpressure through a bounded `mpsc::channel(capacity)` (default `16`) and cancel execution on stream drop.
- **Risks:**
  1. `serde_json::from_slice` recursion limit (`128`) vs hostile deeply nested JSON payloads (`[[[[...]]]]`). Mitigated by running a linear single-pass UTF-8 JSON structural nesting scanner (respecting string literals and escapes, default max depth `64`) before `serde_json` deserialization so deep JSON fails deterministically with `400` (`GAP_PARSE_ERROR`) without stack growth.
  2. Client disconnect / future drop leaving background connector streams alive. Mitigated by holding a `DropGuard` (`CancellationToken::drop_guard`) in the outer HTTP response future and inside the SSE `Stream` state so dropping either the one-shot request future or the SSE response body stream immediately cancels the request `CancellationToken`, dropping `tonic::Streaming` within `< 50 ms` under paused time.
  3. Metric cardinality or secret leakage (`INV-15`, `OPS-011`, `OPS-020`). Mitigated by restricting metric route labels to a closed enum (`RouteLabel`), redacting key material in `Debug` impls, hashing query text with `blake3` for span attributes rather than recording raw queries, and testing with canary secrets and `gap_testkit::TracingCapture`.

# WP-M0-10 steps — Documentation skeleton and agent-facing rules

- **Assumptions:**
  1. `book/book.toml` uses the standard mdBook layout (`src = "src"`, `build-dir = "../target/book"`, `create-missing = false`), placing the table of contents at `book/src/SUMMARY.md` and an introductory landing chapter at `book/src/introduction.md`. Because `book/src/` is two directories below the repository root, relative links from `book/src/SUMMARY.md` to `spec/*.md` and `docs/*.md` use `../../spec/<file>.md` and `../../docs/<file>.md`.
  2. `docs/RELEASE.md` derives its error-budget policy, SLO table, release train, verification cadence, feature flags, and migration/upgrade rules exclusively from `spec/08-operations.md` (`OPS-001`, `OPS-003`, `OPS-030`, `OPS-040`–`OPS-044`), `docs/03-VERIFICATION.md` (`VER-001`–`VER-055`, §8–§10), and `docs/01-DECISIONS.md` (`ADR-002`, `ADR-003`, `ADR-007`, `ADR-009`, `ADR-020`–`ADR-022`, `ADR-024`, `ADR-025`), citing exact normative IDs and introducing zero unmeasured or undocumented numeric thresholds, SLOs, or dates (`ADR-021`).
  3. `docs/UNSAFE.md` is an empty ledger in `M0` establishing the workspace-wide `#![forbid(unsafe_code)]` rule (`ADR-002`, `ARC-003`) with `gap-s1` (`WP-M5-02`) as the sole permitted exception requiring an inline `// SAFETY:` comment and a ledger entry.
  4. `docs/hosts/` provides the `CMP-009` placeholder guides (`docs/hosts/README.md`, `docs/hosts/claude-code.md`, `docs/hosts/antigravity.md`, `docs/hosts/cursor.md`) outlining the stateless `/mcp` Streamable HTTP / stdio facade (`CMP-001`–`CMP-009`, `ADR-017`, `OPS-002`) and recommended permission settings (`gap_search`, `gap_describe`, `gap_query` auto-approved; `gap_mutate` prompted), to be expanded and doc-tested in `WP-M7-03`.
  5. `docs/runbooks/README.md` indexes all nine normative alerts from `spec/08-operations.md` §6 (`SwapStuck`, `AutoRollback`, `BreakerFlapping`, `BranchDrift`, `S1Drift`, `IngestBacklog`, `AuditVerifyFail`, `TaskLeaseExpiry`, `OverloadShedding`) and operator `gap` CLI entry points (`OPS-044`), referencing the per-alert runbook files as planned `WP-M7-04` artifacts rather than broken links (`WP-M0-10` owns `docs/runbooks/README.md` only).
- **Rejected simpler alternative:**
  - *Alternative A:* Place `SUMMARY.md` directly in `book/SUMMARY.md` (`src = "."`) or leave stub `SUMMARY.md` links empty (`[Spec]()`). Rejected because `src = "."` places `book.toml` inside the mdBook source directory (causing config files to be treated as static book assets), and draft `()` links neither link the existing `spec/*.md` and `docs/*.md` files nor verify relative path resolution.
  - *Alternative B:* Duplicate `spec/*.md` and `docs/*.md` files into `book/src/` in `M0`. Rejected because duplicating normative spec files violates single-source-of-truth discipline (`ADR-022`) and creates immediate drift against ongoing spec/review updates.
- **Risks:**
  1. `tools/check_refs.py` scans every `**/*.md` file in the repository for `(ARC|GQL|NGC|RTE|ING|RUN|SEC|OPS|CMP|VER|INV|TM|ADR)-\d{2,3}` tokens and fails on any undefined ID; mitigated by citing only verified normative IDs and running `PYTHONDONTWRITEBYTECODE=1 python3 tools/check_refs.py` after authoring.
  2. Future `WP-M7-03` runs `mdbook test book`, which treats untagged fenced code blocks as Rust doctests; mitigated by tagging every non-Rust code block explicitly (`toml`, `bash`, `json`, `text`).
  3. Uncommitted reviewer edits exist in paths outside `WP-M0-10`'s `owns`; mitigated by staging only explicit `WP-M0-10` paths via `git add` and running Python with `PYTHONDONTWRITEBYTECODE=1`.

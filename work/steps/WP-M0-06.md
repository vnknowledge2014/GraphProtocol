# WP-M0-06 steps — Protobuf pipeline and `gap-proto` crate

- **Assumptions:**
  1. All Cargo builds, tests, lints, and doc builds run strictly offline (`--offline`, with `.cargo/config.toml` already pointing `crates-io` at `.local/vendor`). Because the sandbox blocks `~/.cargo/config.toml`, Cargo commands use `CARGO_HOME=.git/tmp-cargo-home`, and `.git/tmp-cargo-home` is removed before writing the handoff (asking before any `rm -rf`).
  2. `crates/gap-proto/Cargo.toml` declares the exact dependency set specified in `work/context/m0-06-brief.md` §2 (`gap-core`, `prost`, `prost-types`, `tonic`, `tonic-prost` under `[dependencies]`; `protox`, `tonic-prost-build` under `[build-dependencies]`; `proptest`, `prost-reflect`, `sha2` under `[dev-dependencies]`), all as single-line alphabetically sorted `name.workspace = true` entries (`ARC-001`), with no `hex` crate and no edits to root `Cargo.toml` or `.local/`.
  3. No system `protoc` binary is used or invoked; `crates/gap-proto/build.rs` compiles `gap/gateway/v1/gateway.proto` and `gap/ngc/v1/ngc.proto` (from `../../proto`) and, when `CARGO_FEATURE_A2A` is set, `a2a.proto` (from `../../third_party/specs/a2a-v1.0.1/specification` and `../../third_party/specs/googleapis-646596e286b4`) purely in Rust via `protox::Compiler` (`include_source_info(false)`, `include_imports(false)`) and `tonic_prost_build::configure()`.
  4. `tools/spec_trace.py` validates `// spec: <ID>` comments strictly against requirement IDs in `spec/*.md` (`NGC-001`, `NGC-004`, `CMP-020`, `CMP-021`, `CMP-022`), while `tools/check_refs.py` checks every `AREA-nnn` reference across `**/*.md`. Any `ADR-*` citation (`ADR-002`, `ADR-021`, `ADR-022`, `ADR-024`) appears only in prose or error messages, never as a `spec: ADR-...` marker.
- **Rejected simpler alternative:**
  - *Alternative A:* Call `protox::compile(...)` or `tonic_prost_build::compile_protos(...)` directly in `build.rs`. Rejected because `protox::compile` enables `include_source_info(true)` and `include_imports(true)`, which embeds comments and transitive well-known/googleapis descriptors into `DESCRIPTOR_SET` and violates `m0-06-brief.md` §§3.2, 3.4 (comment-only `.proto` edits must not alter the golden SHA-256 digest, and `DESCRIPTOR_SET` / `A2A_DESCRIPTOR_SET` must contain only own files).
  - *Alternative B:* Check generated `.rs` files into `crates/gap-proto/src/` instead of compiling in `build.rs`. Rejected by `m0-06-brief.md` §3.1 ("nothing generated is committed") and because compiling from `.proto` sources in `build.rs` keeps `.proto` files as the single source of truth coupled to `golden/*.sha256` and `CHANGELOG.md`.
  - *Alternative C:* Test round-trip serialization on a hand-picked subset of messages or with static `Arbitrary` derives only. Rejected because `m0-06-brief.md` §3.5 requires dynamic-to-static-to-dynamic wire compatibility via `prost_reflect::DynamicMessage` across **every** non-map-entry message in the descriptor set enforced by a completeness check against `MessageDescriptor::full_name`.
- **Risks:**
  1. `prost_reflect::DynamicMessage` derives `PartialEq` over its internal field map, so setting a proto3 implicit-presence scalar field to its default value (`0`, `false`, `""`, empty `bytes`) leaves an explicit entry in the generator's map that disappears after wire encode/decode. Mitigated by clearing any generated field when `!msg.has_field(&field)` (preserving explicit presence on `oneof`, `proto3_optional`, and message fields while keeping implicit-presence defaults canonical) and generating only finite `f32`/`f64` values (`NaN != NaN`) and valid `Timestamp`/`Struct`/`Value`/`ListValue` payloads.
  2. `A2A_DESCRIPTOR_SET` contains `a2a.proto` only (`include_imports(false)`), while `a2a.proto` declares `dependency` entries on `google/api/{annotations,client,field_behavior}.proto`, which `prost_reflect::DescriptorPool` requires to be loaded prior to `a2a.proto`. Mitigated by keeping `pub const A2A_DESCRIPTOR_SET: &[u8]` strictly `a2a.proto`-only and emitting a separate `$OUT_DIR/a2a_googleapis_imports.bin` helper in `build.rs` (under `CARGO_FEATURE_A2A`) that tests load into `DescriptorPool::global()` before decoding `A2A_DESCRIPTOR_SET`.
  3. `cargo-nextest` is not installed in the sandbox environment. Mitigated by running `cargo test -p gap-proto --locked --offline` and `--all-features` three times each, reporting `cargo nextest` as `NOT RUN` in `work/handoffs/WP-M0-06.md`, leaving `WP-M0-06` in `doing` state, and finishing with `WP-M0-06: READY-WITH-NOT-RUN`.

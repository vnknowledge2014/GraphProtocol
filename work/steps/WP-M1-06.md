# WP-M1-06 steps — `gap-plan` v0 (`ir`, single-branch `planner`, `explain`, `plan_hash`, `moka` `PlanCache`) and `sha2` in `gap-ql`

- **Assumptions:**
  1. All Cargo commands run strictly offline against `.local/vendor` with `CARGO_HOME=.git/tmp-cargo-home --locked --offline`. Per protocol rules, `.git/tmp-cargo-home` is **left in place** for the reviewer to remove; `cargo nextest` is not installed in this sandbox and is reported `NOT RUN` with 3 consecutive `cargo test` runs as the substitute.
  2. The pre-seeded dependency manifests in `crates/gap-ql/Cargo.toml` (`sha2.workspace = true`) and `crates/gap-plan/Cargo.toml` (`apollo-compiler`, `blake3`, `gap-core`, `gap-ql`, `moka` with `features = ["sync"]`, `serde`, `serde_json`, `thiserror`, `tracing`; dev: `proptest`, `tokio`) and `Cargo.lock` require no edits.
  3. `gap-plan` sits at layer `L2` (`gap-core` `L0`, `gap-ql` `L1`); it never depends on `gap-snapshot` (`L3`). RFC 8785 JCS canonicalization lives in `gap-snapshot::canonical`, so `plan_hash` hashes the compact `serde_json::to_string` of the `Plan`'s `serde_json::Value` (where `serde_json::Map` is backed by `BTreeMap`, verified by unit test, and plans emit no floats unless a GraphQL float literal argument is passed).
  4. `@skip` and `@include` directives on selections and fragments are **kept** on `SelectionField.directives` (`SelectionDirective { name, if_arg: ArgValue }`, propagating fragment-level `@skip`/`@include` onto flattened child fields) rather than eagerly evaluated at plan time so that cached plans remain 100% variable-independent (`Brief §3.2`).
  5. `moka::sync::CacheBuilder::weigher` interprets `max_capacity` as maximum total weight rather than entry count (`moka 0.12.16` `base_cache.rs`). `PlanCacheConfig` therefore exposes `max_entries: u64` (default `10_000`, `RUN-014`), `ttl: Duration` (default `3_600 s`), and `max_weight_bytes: Option<u64>` (defaulting to `max_entries * 4_096` bytes when `None`, or an exact byte cap when `Some`), weighing each `Arc<Plan>` by its compact serialized JSON byte length (`>= 1`).
  6. `tools/spec_trace.py` matches `// spec: <ID>` against `spec/*.md` IDs only (`RUN-005`, `RUN-010`, `RUN-011`, `RUN-013`, `RUN-014`, `INV-01`, `INV-02`, `INV-09`, `GQL-040`, `GQL-041`, `GQL-061`); `ADR-009` references appear only in doc comments or parenthetical notes, never as standalone `// spec:` tokens.
- **Rejected simpler alternative:**
  - *Alternative A:* Evaluate `@skip(if: ...)` and `@include(if: ...)` using `ValidatedOperation.coerced_variables` during planning, and resolve `$var` arguments into `ArgValue::Literal`. Rejected because `PlanCacheKey` (`ADR-009` §6, `gap_core::snapshot::PlanCacheKey`) intentionally omits runtime variable values so one cached `Arc<Plan>` serves all variable sets (`Brief §3.2`). Embedding variable values would poison cached plans across callers.
  - *Alternative B:* Merge multiple root fields owned by the same branch into a single `Fetch` node. Rejected because NGC `QueryRequest` executes one `operation` per call (`proto/gap/ngc/v1/ngc.proto`) and `Brief §3.3` explicitly requires root fields of the same branch to remain separate `Fetch` nodes ordered under `Parallel` by `(branch_id, operation, response_key)`.
  - *Alternative C:* Guard `PlanCache` hit/miss counters or coalescing with a `Mutex`/`RwLock`. Rejected because `INV-02` forbids locks in `gap-plan` on the read path; `moka::sync::Cache::entry(key).or_try_insert_with(...)` coalesces concurrent misses internally and exposes `entry.is_fresh()`, while `AtomicU64` tracks hits and misses lock-free.
- **Risks:**
  1. Hostile GraphQL documents (deep selection sets at limit 12, 10,000 root fields, 1 MiB aliases) could blow stack frames or trigger superlinear sorting/serialization. Mitigated by bounded selection-depth recursion, `O(N log N)` tuple sort on `(branch, operation, response_key)`, and pre-sized vectors.
  2. Over-budget requests hitting a warm `PlanCache` with larger list variables (`$first`) or a stricter caller `@budget` / `request_budget_cost_units` could bypass `RUN-005` if cost were checked only on cache miss. Mitigated by running `gap_ql::enforce_operation_cost` in `PlanCache::get_or_plan` before returning cached plans as well as inside `planner::plan`.

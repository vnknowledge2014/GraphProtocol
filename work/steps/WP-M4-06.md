## Steps

1. Create adversarial join verification fixtures in `tests/fixtures/joins/`:
   - `same_type_different_entity.json`: `Order.order_id` (`Int`) -> `User.user_id` (`Int`) with disjoint/low-containment salted bottom-k hashes (must be rejected by G4).
   - `partial_overlap.json`: `Event.account_id` -> `Account.id` with partial containment `< 0.95` (must be rejected by G4).
   - `skewed_duplicates.json`: `Invoice.customer_email` -> `Customer.email` with RHS duplicate keys (`uniqueness_ratio < 0.999`) and high null ratio (must be rejected by G4).
   - `empty_domain.json`: `Draft.org_id` -> `Org.id` with zero samples (`sample_count == 0`, `distinct_estimate == 0`, `exact == true`); must stay `PROPOSED` (never promoted to `VERIFIED` or `ACTIVE`).
   - `valid_customer_orders.json`: `Order.customer_id` -> `Customer.id` with `containment >= 0.95`, `null_ratio <= 0.50`, `uniqueness_ratio >= 0.999`, sufficient distinct samples; promoted `PROPOSED -> VERIFIED -> CANARY -> ACTIVE`.
2. Implement `crates/gap-ingest/src/gates/join_verify/mod.rs`:
   - Tenant-scoped salt & read-only ingestion service principal enforcement (`NGC-051`, `NGC-052`), building `gap_proto::ngc::v1::SketchRequest` with `CallContext`.
   - Bottom-k union containment estimator and error bound (`1.0 / sqrt(k_eff)`) per `NGC-051` (`|bottomk(A) ∩ bottomk(B)|` over the first `k_eff = min(k, |A|, |B|)` hashes of the union's bottom-k), plus exact mode handling when `lhs.exact && rhs.exact`.
   - Gate G4 evaluator enforcing `ADR-012` / `spec/05-ingestion.md` §5 thresholds (`containment >= 0.95`, `null_ratio <= 0.5`, RHS uniqueness `>= 0.999` or declared unique/PK, `sample >= 1_000` or non-empty whole domain `exact`, value-kind compatibility, cardinality consistency).
   - Join lifecycle state machine (`Proposed -> Verified -> Canary -> Active -> Quarantined/Deprecated`) enforcing `INV-06` (`visible_to_planner == true` iff `Active`), `ING-021` (`LLM` candidates require human approval), and `ING-041` canary window (`>= 100` executions or `>= 10 min`) + automatic revert to `Verified` with alert on `> 10` percentage point coverage drop.
   - Unit & fixture tests (`test(join_verify)` and `test(canary)`) tagged `// spec: ING-040, ING-041, NGC-050, NGC-051, NGC-052, INV-06`.
3. Implement `crates/gap-ingest/src/gates/replay/mod.rs`:
   - Gate G8 regression replay (`spec/05-ingestion.md` §5, `ING-040`, `ING-041`, `INV-06`): re-plans top-N (default `200`) cached/persisted operations and conformance fixtures on the candidate shadow `Cisg`, compares read-only shadow execution results (payloads discarded after diffing), and flags breaking vs non-breaking diffs (blocking unless `breaking_change_ack` is present for non-breaking/soft threshold, always blocking breaking diffs without ack and triggering canary revert if coverage drops `> 10` percentage points).
   - Unit tests (`test(replay)` and `test(canary)`) tagged `// spec: ING-040, ING-041, INV-06`.
4. Implement `crates/gap-exec/src/shadow/mod.rs`:
   - Execution-plane `ShadowCanaryRunner` (`ING-041`, `INV-06`) that gates sampled read-only shadow execution, explicitly discards shadow payload bytes so client responses are untouched, compares observed row count and key coverage against sketch containment expectations, and emits `PromoteToActive`, `ContinueCanary`, or `RevertToVerified { alert }` on divergence `> 10` percentage points (`0.10`).
   - Unit tests (`test(shadow)` and `test(canary)`) tagged `// spec: ING-040, ING-041, INV-06`.
5. Run acceptance tests (`gap-ingest` and `gap-exec`), `cargo clippy`, `cargo fmt --check`, and repo checks (`check_layers.py`, `wp.py validate`, `check_refs.py`, `spec_trace.py`), write handoff `work/handoffs/WP-M4-06.md`, commit on `wp/WP-M4-06`, and fast-forward merge to `main`.

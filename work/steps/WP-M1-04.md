# WP-M1-04 steps — NGC connector conformance kit

Implementer: Claude Sonnet 5.5 (the orchestrator, because the usual coder agent ran out of credit on 2026-10-31). Because implementer and reviewer are the same
agent here, the review is made mechanical: independent mutation run of the kit's own checks, flaw matrix, clean-room offline build (see Step 12).

Assumptions
- A1 The kit is black-box over the gRPC binding (`GrpcClient`, NGC-001); HTTP/stdio equality with gRPC is the SDK transport matrix's job (WP-M1-03), not the kit's.
- A2 Which operations/keys to probe is connector-specific data. The kit never guesses it from `Describe`; it reads a profile `conformance/ngc/<name>.kit.toml`.
  The extension is `.toml` on purpose: the GAP fixture loader (`gap-conformance` fixture.rs) walks every `*.json` and rejects unknown keys.
- A3 Every check ends `Pass`, `Fail(reason)` or `Skip(NotApplicable | NotCovered)`. `NotApplicable` = the capability is not advertised. `NotCovered` = advertised but the
  profile has no section for it. `KitReport::compatible()` = no `Fail` and no `NotCovered` (NGC-091: "all applicable fixtures pass, capability-gated").
- A4 Time comes from `tokio::time`, so the self-tests run under paused time (no real sleeps; AGENT-GUIDE §5 rule 4).
- A5 `gap-ql` (L1) may be a dependency of `gap-conformance` (L5): the SDL check uses `gap_ql::schema::with_gap_builtins` (parse + reserved names, NGC-012).

Rejected simpler alternative: reuse the GAP-QL JSON fixture format (`request`/`expect`) for the kit. It cannot express multi-call, stateful checks (idempotent replay,
cursor walk, cancel-then-reuse-capacity) and the loader would reject the files. Hard-coding operation names was rejected too (a kit for one connector only).

Risks
- R1 The SDK core masks deadline/cancel flaws (it drops the connector future itself, NGC-093). The deadline/cancel checks therefore also prove that capacity comes back
  (a fresh batch of slow calls is accepted right after), which exposes a connector that keeps working or holds its own gate. The flaw matrix uses a connector-owned gate.
- R2 A check that only works with the reference data set. Mitigation: every data dependency is a named profile field, documented in `conformance/ngc/README.md`.
- R3 Timing flakes. Mitigation: paused time in self-tests; real runs use profile-configurable grace periods.

## Steps (each ends with a command)
1. `ngc_kit/profile.rs`: TOML schema (`deny_unknown_fields`) + validation + unit tests. Run: `cargo test -p gap-conformance ngc_kit::profile`.
2. `ngc_kit/mod.rs` + `outcome.rs`: `CheckId`, `Outcome`, `KitReport` (+ JSON with spec ids), trait `NgcTarget` (impl for `GrpcClient`), runner. Run: `cargo test -p gap-conformance ngc_kit`.
3. `ngc_kit/reference.rs` (good connector on `MockConnector`, `Flaw` enum) + `checks/describe.rs` (`describe.valid`, `describe.stable`) + `checks/health.rs`.
4. `checks/foreach.rs`: `foreach.correctness`, `foreach.order`, `foreach.n_plus_one`.
5. `checks/deadline.rs`: `deadline`, `cancel` (with the capacity-recovery proof).
6. `checks/mutate.rs`: `mutate.idempotency`, `mutate.dry_run`.
7. `checks/paging.rs`: `page.stability` (traversal equals full read, repeatable, cursor bound to arguments, garbage cursor rejected).
8. `checks/errors.rs`: `errors.mapping` (bad arguments, unknown operation, unadvertised predicate, no credential echo) and `checks/size.rs`: `limits.response_size`.
9. `ngc_kit/selftest.rs` (tests): the good connector passes every check; each `Flaw` fails exactly the checks it targets.
10. `conformance/ngc/sdk-reference.kit.toml` + `conformance/ngc/README.md` (profile reference).
11. `cli.rs`: `--connector-kit --connector <addr> --profile <file> [--report <path>]`; remove the not-implemented stub and update its test.
12. Gates + independent verification + handoff: `cargo nextest run -p gap-conformance -E 'test(ngc_kit)'`, workspace gates, string-mutation run of the kit's own checks,
    clean-room offline build, `work/handoffs/WP-M1-04.md` (AGENT-GUIDE §10).

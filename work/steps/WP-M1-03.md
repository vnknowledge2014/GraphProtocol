# WP-M1-03 steps — `gap-ngc-sdk` (`Connector` trait, gRPC/HTTP/stdio servers, `foreach` helper, mock)

- **Assumptions:**
  1. All Cargo commands execute strictly offline (`--offline`, using `.local/vendor` configured in `.cargo/config.toml`) with `CARGO_HOME=.git/tmp-cargo-home`, and `.git/tmp-cargo-home` is deleted before writing `work/handoffs/WP-M1-03.md`.
  2. `crates/gap-ngc-sdk/Cargo.toml` declares the exact dependency and dev-dependency table of `work/context/m1-03-brief.md` §2 (`ARC-001` workspace dependencies only; `Cargo.lock` updated solely by Cargo; root `Cargo.toml`, `crates/gap-proto/**`, and `crates/gap-core/**` remain untouched).
  3. Tests run inside a socket-restricted, child-process-restricted sandbox: gRPC and stdio tests run over `tokio::io::duplex`, HTTP tests run via `tower::ServiceExt::oneshot` against `axum::Router`, and time-dependent tests use `tokio::time::pause` (`#[tokio::test(start_paused = true)]`) + `gap_core::clock::ManualClock` (`ARC-010`).
  4. `cargo-nextest` is not installed in the sandbox environment; `cargo test -p gap-ngc-sdk --locked --offline` is executed three consecutive times and `cargo nextest` is reported `NOT RUN` in `work/handoffs/WP-M1-03.md`, leaving `WP-M1-03` in `doing` state.
- **Rejected simpler alternative:**
  - *Alternative A:* Hand-write `serde` structs or manual `serde_json::Value` mappers per RPC for HTTP and stdio. Rejected by `m1-03-brief.md` §3.4 and `NGC-002` because hand-written mappers drift from `.proto` descriptors on 64-bit integer stringification, base64 bytes, `google.protobuf.{Struct,Value,Timestamp}`, oneofs, maps, and default-omission rules. Instead, a single `OnceLock<prost_reflect::DescriptorPool>` built from `gap_proto::DESCRIPTOR_SET` drives canonical JSON serialization/deserialization.
  - *Alternative B:* Rely solely on `prost_reflect::DeserializeOptions::new().deny_unknown_fields(false)` when parsing request JSON. Rejected because in `prost-reflect 0.16.5`, `deny_unknown_fields(false)` also causes `EnumVisitor::visit_str` to silently accept unknown enum string names as `None` (default `0`), violating `NGC-002` ("ignore unknown fields like the binary decoder, but reject unknown enum names and wrongly typed values with `INVALID_ARGUMENT`"). Instead, we prune only unknown message object keys guided by `MessageDescriptor` (preserving `google.protobuf.{Struct,Value,ListValue,Timestamp}` payloads) and deserialize with `deny_unknown_fields(true)`.
  - *Alternative C:* Duplicate deadline, cancellation, concurrency-cap, panic-catching, and error-clamping logic inside `grpc.rs`, `http.rs`, and `stdio.rs`. Rejected by `m1-03-brief.md` §3.3 and `NGC-093`; `ServerCore<C>` is the single enforcement point so all three bindings behave identically.
- **Risks:**
  1. Oversized HTTP bodies or stdio lines could allocate unbounded memory before failing (`NGC-093` (f), `NGC-094`, `NGC-095`). Mitigated by reading HTTP request bodies chunk-by-chunk up to `max_request_bytes + 1` under the call/default timeout (returning `413` on overflow and `504` on slow-loris timeout) and scanning stdio input via `AsyncBufRead::fill_buf`/`consume` with a `max_request_bytes` accumulator (emitting `-32600` and ending the session immediately without buffering the rest of an oversized line).
  2. Panics inside synchronous `Connector` method bodies (before returning a future) or inside polled futures/streams could tear down the server or leak panic text (`NGC-093` (d), `NGC-061`). Mitigated by wrapping both synchronous invocation (`std::panic::catch_unwind`) and async future/stream polls (`futures_util::FutureExt::catch_unwind` / `StreamExt::catch_unwind`) in `ServerCore<C>`, mapping panics to `NgcErrorCode::Internal` with the fixed message `"connector panicked"`.
  3. Subtle `foreach` canonical JSON float edge cases (`-0.0` vs `0.0`, object key ordering, `None` vs empty `Struct`) could cause missed deduplication or non-deterministic batching (`NGC-096` (b)). Mitigated by normalizing `f64` zeros (`if v == 0.0 { 0.0 } else { v }` via `to_bits()`) and sorting `Struct` keys recursively into a canonical key representation verified by `proptest` against a naive reference evaluator.

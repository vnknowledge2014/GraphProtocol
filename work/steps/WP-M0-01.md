# WP-M0-01 steps — Repository bootstrap

- **Assumptions:**
  1. Host toolchain already has Rust `1.98.1` (`rustc 1.98.1 (48a229cea 2026-09-01)`), `rustfmt 1.9.0-stable`, `clippy 0.1.98`, Git `2.50.1`, and Python `3.15.0` installed (verified before coding; note that `rustup` stores `1.98.1` under `stable-x86_64-apple-darwin` rather than a separate `1.98.1-x86_64-apple-darwin` directory).
  2. Existing baseline files (`AGENTS.md`, `README.md`, `.agent/`, `docs/`, `proto/`, `spec/`, `tools/`, `work/work-packages.toml`, `work/dag/`) belong in the initial commit on `main`, while `.licenses/` is local Antigravity plugin state and should be ignored by `.gitignore`.
  3. Crates added in `WP-M0-02` will declare `#![deny(clippy::unwrap_used, clippy::expect_used, clippy::panic, clippy::todo, clippy::unimplemented)]` per `ARC-003`, so `clippy.toml` must enable `allow-unwrap-in-tests = true`, `allow-expect-in-tests = true`, and `allow-panic-in-tests = true` alongside `disallowed-methods = []` rather than placing `Option::unwrap` / `Result::unwrap` in `disallowed-methods` (which in Clippy `0.1.98` has no test exemption and would break `#[test]` under `--all-targets`).
- **Rejected simpler alternative:**
  - *Alternative A:* Put `core::option::Option::unwrap`, `core::result::Result::unwrap`, `core::option::Option::expect`, and `core::result::Result::expect` directly in `clippy.toml` `disallowed-methods`. Rejected after verifying `clippy-driver 0.1.98`: `clippy::disallowed_methods` fires in `--test` builds with no `allow-*-in-tests` toggle, which would violate the "unwrap/expect outside tests" scope when `WP-M0-02`+ runs `cargo clippy --workspace --all-targets -- -D warnings`.
  - *Alternative B:* Commit everything (baseline + `WP-M0-01` deliverables) in a single commit on `main`. Rejected because `WP-M0-01` explicitly requires the first commit to contain the pre-existing `docs/spec/work/tools` and `ADR-022` requires one WP per branch (`wp/WP-M0-01`).
- **Risks:**
  1. `but setup` writes to the global GitButler project registry outside this repository and adds a `gb-local` git remote (`but setup --help`), which is blocked by the sandbox and forbidden by the "no remote, nothing outside this directory" constraint; mitigated by falling back cleanly to plain `git` with branch `wp/WP-M0-01`.
  2. Once `rust-toolchain.toml` pins `channel = "1.98.1"`, `rustup` looks for `1.98.1-x86_64-apple-darwin` (currently installed under `stable-x86_64-apple-darwin`) and attempts an online sync if invoked without a local toolchain link; mitigated during offline verification via an ephemeral repo-local `RUSTUP_HOME` symlink inside `.git/` (cleaned up afterwards) and documented in the handoff for host setup (`rustup toolchain link`).
  3. Any placeholder requirement token in `.md` files (e.g., an undefined `AREA-nnn` example) would fail `tools/check_refs.py`; mitigated by citing only defined IDs (`ADR-002`, `ADR-022`, `ADR-024`, `ARC-003`, `OPS-040`, `ADR-013`, `ADR-014`, `INV-04`, `INV-07`, `INV-09`, `INV-15`).

# WP-M0-05 steps — Wire planning/architecture tools into CI with tests

- **Assumptions:**
  1. `tools/wp.py`, `tools/check_layers.py`, and `tools/check_refs.py` already implement the normative CLI behaviours required by `ADR-022`, `ARC-001`, and `ARC-002`, and expose module-level `ROOT` (plus `WP_FILE` and `STATUS_FILE` in `tools/wp.py`) constants that can be patched via `unittest.mock.patch.object` against `tempfile.TemporaryDirectory` fixtures without altering any tool's CLI behaviour or real-repository output.
  2. `tools/check_layers.py` runs `cargo metadata --format-version 1 --locked` in `ROOT`. Hermetic temporary Cargo workspaces with path-only dependencies (`resolver = "2"`, `edition = "2021"`), `cargo generate-lockfile --offline`, and isolated `CARGO_HOME` / `__CARGO_TEST_ROOT` environment variables inside the temporary directory need no network or registry access.
  3. `tools/layers.toml` already lists all 31 root-workspace crates (`crates/*`, `adapters/*`, `bench/*`: 30 in `[layers]` plus `gap-testkit` in `[exempt_dev]`). `fuzz/Cargo.toml` (`package.name = "gap-fuzz"`) is a standalone `cargo-fuzz` workspace (`[workspace]` + `package.metadata.cargo-fuzz = true`) explicitly listed in root `Cargo.toml` `[workspace].exclude = ["fuzz", "bench/results"]`, and `crates/gap-testkit/src/lib.rs` asserts that `tools/layers.toml` (`[layers] U [exempt_dev]`) equals the root workspace member crates. Therefore the repository completeness test walks `crates/`, `adapters/`, `bench/`, `fuzz/`, and `sdks/`, skips directories excluded as standalone workspaces in root `Cargo.toml` `[workspace].exclude` (while verifying that any such excluded manifest defines its own standalone `[workspace]`), and verifies exact bidirectional equality with `tools/layers.toml`.
  4. `tools/check_refs.py` requires `docs/03-VERIFICATION.md`, `spec/01-architecture.md`, `spec/07-security.md`, and `docs/01-DECISIONS.md` to exist under `ROOT` when computing `defined_ids()`.
- **Rejected simpler alternative:**
  - *Alternative A:* Invoke each tool only against the live repository and assert exit code `0`. Rejected because positive-only smoke tests do not catch regressions or single-line mutations (flipped comparisons or deleted validation branches).
  - *Alternative B:* Refactor `tools/wp.py`, `tools/check_layers.py`, and `tools/check_refs.py` to thread a `root: Path` parameter through every function. Rejected because `unittest.mock.patch.object` on module-level `ROOT` / `WP_FILE` / `STATUS_FILE` provides a clean test seam while keeping the production scripts completely untouched and byte-identical.
  - *Alternative C:* Unconditionally include `fuzz/Cargo.toml` (`gap-fuzz`) as a root-workspace crate in `tools/layers.toml`. Rejected because `fuzz` is excluded from the root Cargo workspace (`[workspace].exclude`) and adding `gap-fuzz` to `tools/layers.toml` would break `crates/gap-testkit`'s `workspace_crates_match_layers_and_workspace_deps` check (`ARC-001`).
- **Risks:**
  1. `tools/check_refs.py` scans `tools/*.py` and `**/*.md` for tokens matching area prefixes followed by 2–3 digits and fails on undefined IDs; mitigated by constructing deliberate fake IDs dynamically at runtime (e.g., `"GQL" + "-" + "999"`) and never writing fake literals in test files, step files, or handoff notes.
  2. Sandbox restrictions block reading global `~/.config/git/config` and `~/.cargo/config.toml`; mitigated by passing `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_SYSTEM=/dev/null` to `git`, isolating temporary Cargo workspaces with `CARGO_HOME` / `__CARGO_TEST_ROOT` inside the `TemporaryDirectory`, and cleaning up `.git/tmp-cargo-home` immediately after real-repo `check_layers.py` runs.
  3. Python bytecode `__pycache__` generation could pollute `tools/`; mitigated by always setting `PYTHONDONTWRITEBYTECODE=1` (and `-B` in subprocess calls).

# WP-M0-07 steps — Spec traceability tool

- **Assumptions:**
  1. Normative requirement identifiers in `spec/*.md` appear in two structural forms matching `tools/check_refs.py` and `spec/00-conventions.md` §2: bold requirement headers (`**ARC-001**`, `**RTE-040 (title).**`, including multi-line list items and shared-line bold IDs) and table-defined first-column IDs (`| INV-nn |` and `| TM-nn |`), outside fenced code blocks.
  2. Per `spec/00-conventions.md` §1–§2 (RFC 2119 / RFC 8174), a requirement is classified as a `MUST` iff its extracted text contains uppercase whole-word `MUST` (which covers both `MUST` and `MUST NOT`) and is not marked `(withdrawn)`.
  3. Test markers across `crates/**`, `adapters/**`, `tests/**`, and `conformance/**` appear either as `spec: <ID>` comments/attributes (e.g., `// spec: ARC-001, INV-01`, `#[doc = "spec: RUN-001"]`, `/* spec: TM-01 */`, `# spec: GQL-001`) or as `"spec": ["GQL-001", ...]` fields in JSON conformance fixtures (`VER-010`). In M0 (before `WP-M0-02` / `WP-M0-09`), those four directories do not exist yet, so missing scan roots must be treated as zero markers rather than errors.
  4. In `--milestone Mx` mode (`VER-001`), uncovered-MUST checking is restricted to requirement IDs referenced by `spec_refs` of work packages with `milestone == Mx` in `work/work-packages.toml`, while unknown-ID validation still checks markers against the full set of IDs defined in `spec/*.md` so tests written in earlier milestones (e.g., `M0` markers during `--milestone M1`) are recognized as valid.
- **Rejected simpler alternative:**
  - *Alternative A:* Single line-by-line regex `r"\*\*([A-Z]+-\d+)\*\*.*MUST"` for `spec/*.md` and `r"spec:\s*([A-Z]+-\d+)"` for tests. Rejected because (1) bold headers in `spec/*.md` can include parenthetical titles before the closing `**` (e.g., `**RTE-040 (title).**`), (2) `MUST` / `MUST NOT` can appear on indented continuation lines or sub-bullets of a requirement, and (3) `conformance/**/*.json` fixtures record coverage via JSON `"spec": ["GQL-001", "GQL-002"]` arrays (`spec/00-conventions.md` §2, `VER-010`) and Rust comments can list comma-separated IDs (`spec: GQL-001, GQL-002`).
  - *Alternative B:* Restrict known IDs in `--milestone Mx` to only `Mx`'s `spec_refs`. Rejected because `WP-M1-13` and later milestone gates run `python3 tools/spec_trace.py --strict --milestone Mx` on a workspace that already contains valid `spec: <ID>` markers from earlier milestones; treating earlier-milestone spec IDs as unknown would break every milestone gate from `M1` onward.
- **Risks:**
  1. `tools/check_refs.py` scans `tools/*.py` and `**/*.md` for tokens matching `\b(ARC|GQL|NGC|RTE|ING|RUN|SEC|OPS|CMP|VER|INV|TM|ADR)-\d{2,3}\b` and fails if any matched token is undefined in the repository; mitigated by using only real defined IDs or the `TST-*` test prefix (or runtime string concatenation `"ARC-" + "999"`) in `tools/test_spec_trace.py`, `tools/spec_trace.py`, `work/steps/WP-M0-07.md`, and `work/handoffs/WP-M0-07.md`.
  2. Markdown files under `conformance/` (such as `conformance/README.md` planned in `WP-M0-09`) or build directories (`target/`, `node_modules/`, `__pycache__/`) could contain illustrative `spec:` snippets; mitigated by skipping `.md` files and build/cache directories during test-marker scanning.
  3. Concurrent reviewer edits exist in uncommitted paths outside `WP-M0-07`'s `owns`; mitigated by staging only explicit `WP-M0-07` paths (`tools/spec_trace.py`, `tools/test_spec_trace.py`, `work/steps/WP-M0-07.md`, `work/handoffs/WP-M0-07.md`, `work/status.toml`) and running Python with `PYTHONDONTWRITEBYTECODE=1`.

## Step 2 — Write failing TDD unit tests in `tools/test_spec_trace.py`

File: `tools/test_spec_trace.py` (new)

Content summary (standard-library `unittest` + `tempfile.TemporaryDirectory` fixtures):
- `test_extract_requirements_bullets_tables_and_fences`: verifies extraction of standard bold bullets (`**ARC-001**`), titled bold bullets (`**RTE-040 (Unmapped domain).**`), multi-line continuation bullets with `MUST` / `MUST NOT`, non-MUST bullets (`SHOULD` / lowercase `must`), `(withdrawn)` bullets (`GQL-001`), table-defined `INV-01` / `INV-02` and `TM-01` rows, and ignoring fenced code blocks (`TST-888`).
- `test_scan_markers_across_roots_and_formats`: verifies marker scanning across `crates/**`, `adapters/**`, `tests/**`, and `conformance/**` for `// spec: ARC-001, INV-01`, `#[doc = "spec: CMP-001"]`, `/* spec: TM-01 */`, `# spec: RUN-001`, and JSON `"spec": ["GQL-001", "GQL-002"]`, while skipping `conformance/README.md` and `target/`.
- `test_warn_and_strict_modes`: verifies default (`--warn`) exits `0` while reporting uncovered MUSTs and unknown test IDs (`TST-999` and `"ARC-" + "999"`), `--strict` exits `1` on uncovered MUSTs, `--strict` exits `1` on unknown test IDs even when all MUSTs are covered, and `--strict` exits `0` when all MUSTs have markers and zero unknown IDs exist.
- `test_milestone_filtering`: verifies `--strict --milestone M1` restricts uncovered-MUST enforcement to `M1`'s `spec_refs` in `work/work-packages.toml`, accepts valid markers from other milestones (`ARC-005`), rejects unknown IDs (`TST-999`), and exits `1` on an unknown milestone (`M9`).
- `test_cli_missing_scan_dirs_and_footer`: runs `tools/spec_trace.py --root <tmp> --warn` as a subprocess when `crates/`, `adapters/`, `tests/`, and `conformance/` are absent and asserts exit `0` and 3-line summary output.

## Step 3 — Implement `tools/spec_trace.py`

File: `tools/spec_trace.py` (new)

Content summary:
- Pure Python 3.11+ (`argparse`, `collections`, `dataclasses`, `json`, `pathlib`, `re`, `sys`, `tomllib`).
- `extract_requirements(root: Path) -> dict[str, Requirement]`: parses `spec/*.md` outside fenced code blocks, extracting bold `**XXX-nnn**` (including titled `**XXX-nnn (...).**` and multi-line bullets) and table-defined `| INV-nn |` and `| TM-nn |` rows; classifies `is_must` by uppercase `\bMUST(?:\s+NOT)?\b` when not `(withdrawn)`.
- `scan_test_markers(root: Path) -> dict[str, list[MarkerHit]]`: walks existing `crates`, `adapters`, `tests`, and `conformance` trees (skipping `.md` docs and `target`/`node_modules`/`__pycache__`/`.git`), extracting `spec: <ID>[, <ID>...]` markers from source/test files and `"spec"` string/list entries from `.json` fixtures.
- `load_milestone_filter(root: Path, milestone: str) -> tuple[set[str], set[str]]`: reads `work/work-packages.toml` via `tomllib` and collects exact and `AREA-*` wildcard `spec_refs` for `milestone`.
- `run_trace(root: Path, milestone: str | None = None) -> TraceReport` and `main(argv: list[str] | None = None) -> int`: implements `--warn` (default), `--strict`, `--milestone Mx`, and `--root <dir>`, printing uncovered MUSTs, unknown test IDs, and a 3-line summary footer (`Scope: ...`, `Issues: ...`, `OK|WARN|FAIL: ...`).

Run:
```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest tools.test_spec_trace
```
Expected: `Ran 5 tests ... OK` (TDD green phase, exit 0).

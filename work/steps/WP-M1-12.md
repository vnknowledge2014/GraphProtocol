# WP-M1-12 steps — `gap-server` and `gap-cli` v0 (wiring, config, serve/init/doctor) and `examples/walking-skeleton`

Assumptions
- A1 Scope is `WP-M1-12` (`work/work-packages.toml`, `work/context/m1-12-brief.md`, `work/context/m1-12-transport.md`): `crates/gap-server/**`, `crates/gap-cli/**`, and `examples/walking-skeleton/**` only. Existing stub modules owned by later WPs (`crates/gap-server/src/wiring_s1.rs`, `crates/gap-cli/src/proposals/mod.rs`, `crates/gap-cli/src/calibrate/mod.rs`, `crates/gap-cli/src/commands/mod.rs`) remain untouched and exported.
- A2 `gap.toml` is modelled by `gap_core::config::GapConfig`. `ServerFile` loads via `GapConfig::load_from_path_with_process_env` (with an injectable env helper for deterministic tests without `unsafe` `set_var`), resolves relative `branches[i].openapi.spec` paths against `gap.toml`'s parent directory, verifies every referenced OpenAPI file exists and is readable (failing with `branches[i].openapi.spec`), and resolves `SecretRef` (`env://`, `file:///`; `secret://` fails closed until `WP-M6-07` vault) into `SecretString` without ever echoing secret material (`INV-15`).
- A3 Branch `uid` uses the configured `BranchUid` when present, or derives a deterministic RFC 9562 UUIDv7 (`BranchUid::from_unix_ms`) from a domain-separated `blake3` digest of `branch.id`. Any startup `Describe` or `gap_snapshot::compose` failure is a deterministic startup error naming the branch (`Brief §3.2`).
- A4 All tests are 100% in-process without OS sockets or child processes (`tower::ServiceExt::oneshot` on `gap_transport::router`, `BranchFactory` seam with `gap_ngc_openapi::Upstream` and `gap_mcp::outbound::fake::FakeMcpServer`, `tokio::io::duplex` for `serve_stdio`, and an injected signal stream + exit hook for `Shutdown`). Loopback TCP tests carry `#[ignore = "needs loopback sockets"]`.
- A5 `CARGO_HOME=.git/tmp-cargo-home` is used for all `cargo` commands and left in place (not deleted, documented in the handoff). `cargo nextest` and `cargo deny` are unavailable in this sandbox and reported `NOT RUN`.

Rejected simpler alternative: hard-code `OpenApiConnector<HttpUpstream>` / `McpConnector<HttpTransport<ReqwestPost>>` inside `assemble` and poll OS signals directly inside the `shutdown` future passed to `gap_transport::serve`. Rejected because hard-coded HTTP/child transports cannot be tested deterministically in a socket-free, child-process-free sandbox, and `gap_transport::serve` stops polling `shutdown` once the first signal initiates draining — so a second `SIGTERM`/`SIGINT` during the drain window would be ignored unless supervised alongside the drain (`RUN-090`).

Risks
- R1 `AppState::with_http_module` consumes `AppState` by value while `McpFacade` requires `TransportEngine::new(Arc<AppState>)`. Mitigation: construct shared `Arc` handles (`SnapshotHandle`, `ConnectorRegistry`, `PlanCache`, `TransportMetrics`, `draining: Arc<AtomicBool>`) once so `TransportEngine` and the outer `AppState` share identical lock-free state without `Arc` cycles.
- R2 Stdout protocol corruption in `gap serve --stdio` (`CMP-001`, `OPS-011`). Mitigation: route `tracing-subscriber` exclusively to `stderr` via an injectable `LogStreams` writer (production `std::io::stderr`) and verify in-process that emitted log records land on `stderr` while `stdout` contains valid JSON-RPC `2.0` frames only.
- R3 Symlink escape or unintended file clobbering in `gap init [DIR] [--force]`. Mitigation: validate `DIR` and inspect `symlink_metadata` on every target directory and file inside `DIR`, refusing symlinks unconditionally (even with `--force`) and refusing existing regular files unless `--force` is passed.

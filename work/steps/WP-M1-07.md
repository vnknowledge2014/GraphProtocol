# WP-M1-07 steps — `gap-exec` v0 (`ExecLayer` over `Fetch`/`Parallel`/`Sequence`, `ConnectorLayer` v0, incremental response assembly, and NGC error mapping)

- **Assumptions:**
  1. All Cargo commands run strictly offline against `.local/vendor` with `CARGO_HOME=.git/tmp-cargo-home` and `--locked --offline`. Per protocol rules, `.git/tmp-cargo-home` is **left in place** for the reviewer; `cargo nextest` is not installed in this sandbox and is reported `NOT RUN` with 3 consecutive `cargo test -p gap-exec --locked --offline` runs as the substitute.
  2. `crates/gap-exec/Cargo.toml` and `Cargo.lock` were pre-seeded offline by the reviewer (`apollo-compiler`, `futures-util`, `gap-balance`, `gap-core`, `gap-ngc-sdk`, `gap-plan`, `gap-proto`, `gap-ql`, `gap-sec`, `gap-store`, `prost-types`, `serde`, `serde_json`, `thiserror`, `tokio`, `tokio-util`, `tower`, `tracing`; dev: `proptest`, `tokio`) and require no dependency edits.
  3. `gap-exec` sits at layer `L3` (`tools/layers.toml`), the same layer as `gap-snapshot` (`L3`), so `gap-exec` must not depend on `gap-snapshot`; integration tests construct two-branch `Snapshot` values directly via `gap_core::snapshot::*` and `gap_ql::with_gap_builtins`.
  4. All existing placeholder module declarations in `crates/gap-exec/src/lib.rs` (`bulkhead`, `columnar`, `connector_layer`, `join`, `mutate`, `saga`, `shadow`, `tasks`, `traverse`) remain intact alongside the new `pub mod exec;`.
  5. `ConnectorRegistry` is an immutable `BTreeMap<BranchUid, RegisteredBranch>` built before serving (`INV-02`: zero `Mutex`/`RwLock` on the read path). In v0, "pooling" means one multiplexed `Arc<dyn BranchClient>` per branch, paired with a `tokio::sync::Semaphore` initialized from `BranchDescriptor.limits.max_in_flight` and acquired exclusively via `try_acquire_owned` (`GAP_OVERLOADED` on saturation, never queueing), holding the RAII permit across stream opening and the full lifetime of the returned `BoxStream<QueryResponse>`.
  6. `ExecResponse.data` is `Option<serde_json::Value>`: `Some(Value::Object(..))` when `data` is populated, and `None` (serializing as `"data": null`) when top-level non-null propagation, pre-execution variable validation, or incremental `max_response_bytes` truncation nulls/aborts `data`. Accordingly, `extensions.partial = data.is_some() && !errors.is_empty()` (`GQL-051`, `Brief §3.4`).
  7. `tools/spec_trace.py` matches `// spec: <ID>` against `spec/*.md` normative IDs (`RUN-001`, `RUN-015`, `RUN-024`, `RUN-030`, `RUN-031`, `RUN-060`, `GQL-050`, `GQL-051`, `NGC-020`, `NGC-025`, `NGC-060`, `NGC-061`, `NGC-063`, `NGC-071`, `INV-01`, `INV-02`, `INV-12`, `INV-15`).
- **Rejected simpler alternative:**
  - *Alternative A:* Spawn detached `tokio::spawn` tasks for `PlanNode::Parallel` children. Rejected because a caller dropping the `ExecLayer` future could leave orphaned tasks briefly alive (`Brief §4`: "an executor future dropped by the caller does the same; no task outlives the response"). Driving concurrent child futures in-place with `futures_util` + a local `Semaphore(max_parallel_fetches)` guarantees synchronous RAII drop of every child future, permit, and `tonic::Streaming` handle the instant the executor future is dropped or `req.cancel` fires.
  - *Alternative B:* Collect all `RowSetChunk` items into a `Vec`, project the full `data` JSON value, and then check `serde_json::to_vec(&data).len() <= max_response_bytes`. Rejected because `RUN-060` and `Brief §3.4`/`§4`/`§6` forbid building the full body before checking size and require early stream termination against hostile endless/giant connectors. Instead, we account exact compact UTF-8 JSON bytes incrementally as each row/field is projected and drop the stream immediately upon exceeding `max_response_bytes`.
  - *Alternative C:* Pass connector `NgcError.message` and `details` straight through to `GraphqlError`. Rejected because branch text is untrusted (`INV-15`, `NGC-061`, `Brief §3.5`): `details` is dropped, control characters/ANSI sequences/stack traces are scrubbed, credential patterns and registered secrets are redacted, and messages are clamped to `<= 300` Unicode scalar values.
- **Risks:**
  1. Incremental byte accounting drifting from serialized JSON at exact-fit boundaries (`== cap` passes, `cap + 1` fails). Mitigated by computing exact RFC 8259 / `serde_json` compact UTF-8 byte lengths per key, punctuation token, string escape, number, boolean, and `null`, ajustar-updating subtree byte counts if a nullable ancestor absorbs a non-null violation, and asserting equality against `serde_json::to_vec(&data)` in tests.
  2. Cancellation over `in_memory_grpc` taking > 50 ms if `GrpcClient` does not drop `tonic::Streaming` on `CallScope::cancel`. Mitigated by wrapping both RPC stream open and `Stream::poll_next` in `GrpcClient`'s `BranchClient` implementation with `scope.cancel` and `scope.deadline`, immediately dropping `tonic::Streaming` (emitting HTTP/2 `RST_STREAM`) on cancel, deadline, or stream drop.

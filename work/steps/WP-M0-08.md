  2. Only the approved third-party dependencies for `WP-M0-08` are added to `crates/gap-core/Cargo.toml` (`apollo-compiler`, `schemars` with `derive`, `serde` with `derive`, `serde_json`, `thiserror`, `toml`, `tracing`, `tracing-subscriber` with `env-filter`/`fmt`/`json`, `uuid` with `serde`/`v4`/`v7`, `zeroize` with `derive`, optional `opentelemetry`/`opentelemetry_sdk`/`opentelemetry-otlp` (`grpc-tonic`, `trace`, `default-features = false`)/`tracing-opentelemetry` behind feature `otel` off by default, and dev-dependency `proptest`). Each line in `[dependencies]` and `[dev-dependencies]` uses single-line `workspace = true` syntax so `gap-testkit::workspace_crates_match_layers_and_workspace_deps` (`ARC-001`) continues to pass.
  3. Because `gap-core` is layer `L0` (`tools/layers.toml`) and cannot depend on `gap-proto`, `crates/gap-core/src/error.rs` defines `NgcErrorCode` and `NgcErrorInfo` mirroring `proto/gap/ngc/v1/ngc.proto` (`NgcError`) with bidirectional `From`/`TryFrom` conversions to and from `GapError` (`NGC-060`); conversion to/from the prost-generated `NgcError` belongs to `gap-proto` / `gap-ngc-sdk` (`WP-M1-03`).
  4. Because `im` is not in the `WP-M0-08` dependency set, `Snapshot.branches` and `Snapshot.groups` (`spec/01-architecture.md` §4 sketch) use immutable `Arc<BTreeMap<BranchUid, Arc<BranchDescriptor>>>` and `Arc<BTreeMap<GroupId, Arc<CapabilityGroup>>>`, preserving structural sharing of `Arc<BranchDescriptor>` and `Arc<CapabilityGroup>` across generations (`ARC-005`).
  5. `tools/spec_trace.py` validates `spec: <ID>` markers in `crates/**` exclusively against requirement IDs defined in `spec/*.md` (not `ADR-*` headings from `docs/01-DECISIONS.md`). Every test carries `// spec: <SPEC_ID>` for `spec/*.md` IDs (`ARC-005`, `ARC-006`, `ARC-010`, `INV-09`, `INV-15`, `GQL-004`, `GQL-070`, `GQL-071`, `GQL-072`, `NGC-060`, `OPS-010`, `OPS-011`) and places ADR references in parenthetical or `// adr:` comments so `spec_trace.py` reports `0 unknown test IDs`.
- **Rejected simpler alternative:**
  - *Alternative A:* Use `String` aliases or unvalidated serde derives for `TenantId`, `BranchId`, `OperationId`, `GroupId`, and `SecretRef`. Rejected because invalid slugs, non-v7 UUIDs, `__`-prefixed operation names (`GQL-004`), or inline plaintext credentials (`INV-15`) could slip in through deserialization (`gap.toml` or wire JSON) and bypass validation.
  - *Alternative B:* Use `async fn` directly in `Embedder`, `DiscoveryService`, `GraphqlEngine`, and `HttpModule`. Rejected because native `async fn` traits are not `dyn`-compatible in Rust, preventing `Arc<dyn DiscoveryService>`, `Arc<dyn Embedder>`, `Arc<dyn GraphqlEngine>`, and `Arc<dyn HttpModule>` upward injection at `gap-server` (`ARC-007`). `BoxFuture<'a, ...>` (`Pin<Box<dyn Future<...> + Send + 'a>>`) keeps every shared trait object-safe with zero extra crates.
- **Risks:**
  1. `opentelemetry-otlp`'s `with_tonic().build()` invokes `tonic::transport::Endpoint::connect_lazy()`, which requires an active Tokio reactor when given a valid URI, whereas `gap-core` does not depend on `tokio`. Mitigated by exposing a generic `SpanExporter`-backed builder path alongside the OTLP gRPC builder so `--features otel` unit tests exercise real `SdkTracerProvider` + `tracing_opentelemetry::layer()` span export synchronously via `SimpleSpanProcessor` and verify invalid OTLP URI rejection without needing a Tokio runtime.
  2. `cargo-nextest` is not installed on this host and must not be installed. Mitigated by running `cargo test -p gap-core --all-features --offline`, recording acceptance command 1 as `NOT RUN` under Deviations, and leaving `WP-M0-08` in `doing` state.

## Hand-over Notes for Downstream Work Packages

### 1. `WP-M2-02` (`gap-ngc-code`: tree-sitter code/doc graph indexer)
- **Deterministic IDs & scope:** Write extracted code/doc symbols and files with `ScopeSpec::Global` and `NewNode { id: Some(NodeId::new(...)?), .. }` following `ING-061` (`<lang>:<repo>:<relpath>#<symbol>`). Set `EdgeResolution::Exact` (`confidence: Some(1.0)`) or `EdgeResolution::Heuristic` (`confidence: Some(0.0..=1.0)` per `ING-060`).
- **Chunked atomic ingestion:** Batch writes via `ContextStore::put_batch(&tenant_scope, &ingester_caller, &nodes, &edges)` in chunks where `nodes.len() + edges.len() <= MAX_BATCH_ITEMS` (`10,000`). Within a batch, all `nodes` are applied before `edges` in one `IMMEDIATE` transaction, so edges may reference nodes introduced in the same batch.
- **Idempotence & removals (`ING-062`):** Re-putting an unchanged `Global` node or edge is a content-hash (`blake3`) no-op and creates no extra version row. When a file or symbol disappears, call `ContextStore::tombstone_node(&tenant_scope, &ingester_caller, &node_id)` — it closes both the node and its active incident edges (`valid_to = now`) while keeping historical `as_of` queries intact (`ADR-020`).

### 2. `WP-M2-03` (`gap.traverse`, `gap.node`, signed cursors, `Predicate`)
- **Upper-layer filtering & field projection:** Because `gap-store` (`L1`) does not depend on `gap-ql` (`ARC-002`, `tools/layers.toml`), `where: Predicate` filtering and `returnFields` projection (`GQL-043`) must be applied in `WP-M2-03` over the `Node` / `Edge` slices returned by `ContextStore::traverse` and `ContextStore::get_node`.
- **Signed cursor construction (`GQL-040`, `GQL-041`):** `TraverseResult` returns `as_of: Timestamp` (resolved once at microsecond precision) and `resume: Option<TraverseResume>` (`Serialize + Deserialize`). Wrap `(tenant, query_parameters_hash, result.as_of, resume)` inside the gateway's HMAC-signed cursor, and pass `as_of: Some(cursor.as_of)` + `after: Some(cursor.resume)` when resolving the next page.
- **Truncation vs pagination:** `TraverseResult.truncated == true` means `visited_cap` (`ING-064`) halted exploration while reachable visible nodes remained; `TraverseResult.resume.is_some()` means additional visited nodes exist beyond the current `first` page.
- **Wire-safe errors (`INV-15`):** Convert any `StoreError` via `err.into_gap_error(correlation_id)` (`StoreError::Invalid` maps to `GAP_VALIDATION_ERROR`; all internal/storage variants map to opaque `GapError::internal(correlation_id)`).
- **Async integration:** `ContextStore` is synchronous; invoke it from async `gap-exec` resolvers via `tokio::task::spawn_blocking`.

## What it is

1. **The offline server.** The runner promised `--offline` ("provided in WP-M1-02 / WP-M1-08") but no work package owned it. Now `gap-conformance --offline <DIR>` composes each fixture `schema` (a branch SDL) with `gap_snapshot::compose`, serves it through the real `gap_transport::router`
   (dev profile, generated API keys per named principal) over an in-memory NGC connection and answers every operation with a completed empty row set; so request errors, limits and cost are real and executed fields resolve to `null` / `[]`. No sockets.
2. **The corpus** (`conformance/gql`, 57 fixtures, class Core 54 + Discovery 3): valid documents, parse failures (`400`), validation failures (`422`), variable coercion, limits (depth, aliases, root fields at and over the maximum), the cost formula (`planned` cost computed by hand from GQL-041), generation, persisted-operation hash, deadline extension.
   Expectations were written from the specification, then compared with the server; every disagreement was classified (fixture mistake vs defect) before anything was changed.
3. **The differential harness** (`tests/differential`): 63 documents, one per GraphQL validation rule family, each with the verdict the GraphQL specification requires. `gap-ql` must produce it (always-on test) and graphql-js (pinned 16.13.2 in `package.json`) must agree except for documented `allow` entries (`#[ignore]` test, needs `node` and `GAP_GRAPHQL_JS_DIR`).
4. **The fuzz target** `fuzz_gapql_parse`: parse, the GAP structural checks and full validation against a fixed schema, no panic on any UTF-8 input.

## Defects found and fixed (this is what the corpus is for)

* **D-1 (high, GQL-002 / GraphQL "CoerceVariableValues") operation variable defaults were ignored.** `query Q($n: Int = 1) { orders(first: $n) }` sent no `first` to the connector; `query Q($id: ID! = "7") { order(id: $id) }` failed with `GAP_VALIDATION_ERROR` *after* planning
  (HTTP 200 with `data: null`, an execution-phase error for a request error). Cause: `gap-transport` handed the executor the raw request variables instead of the validator's coerced map, and `gap-exec` binds only the *schema* argument default. Fix: execute with `validated.coerced_variables`
  (defaults applied, undeclared variables dropped, input coercion done once). Regression test `gap-transport/tests/variables.rs` (fails without the fix: shown).
* **D-2 (medium, GQL-002) `UniqueInputFieldNames` was not enforced**: `{ orders(filter: {status: PAID, status: OPEN}) { id } }` validated. `apollo-compiler` lacks the rule; graphql-js and the specification have it. Found by the differential corpus (62 of 63 verdicts agreed on the first run). Fix: `gap_ql::validate_unique_input_object_fields`, run by the validation pipeline
  (arguments, directive arguments, variable defaults, fragment definitions, inline fragments, nested lists/objects). Unit test + corpus entry.

## Findings that are not defects of this work package

* **F-1 introspection and discovery root fields are refused in M1** (`{ __typename }`, `{ __schema {..} }`, `gap.metaGraph`: `GAP_UNSUPPORTED_FEATURE`, the planner never plans built-in roots). `{ __typename }` is valid GraphQL; the three fixtures are class `Discovery` and close with `WP-M2-05`. The M1 gate must therefore say "Core subset", not "all of GQL-001/GQL-024".
* **F-2 composition namespaces branch types** (`shop_Order`, RUN-009): fragments and variable types in client documents must use the namespaced name; error messages show it. By design, but worth a sentence in the host guides (M7).
* **F-3 the fixture format cannot express HTTP method, headers or a persisted-only request** (no `query`): transport cases (`405`, `406`, `415`, `GET`) stay in `gap-transport` tests. Extending `FixtureRequest` is a follow-up if GQL-003 needs black-box coverage.
* **F-4 `--spawn` is still unimplemented** (`WP-M1-12`/`WP-M1-13` per the runner message); the M1 gate acceptance depends on it.

## Hand-over for WP-M3-04 (`ConnectorLayer v1`)

`crates/gap-exec/src/connector_layer/**` (`WP-M3-04`) composes `gap-balance` without modifying `gap-core`'s `BranchDescriptor` (`m3-01-design.md` §1):

1. **Slot Registration (cold path, snapshot publish / startup):**
   - Construct one process-wide `TelemetryRegistry::new(clock, max_slots)` (default `max_slots = 65_536`, `RTE-078`).
   - Register each tenant-scoped branch with `TelemetrySlotKey::new(tenant_id, branch_uid)` (or the gateway's reserved key for `shared` branches, `RTE-072`) and `SlotParams { max_in_flight: branch.limits.max_in_flight, default_timeout_ms: branch.limits.timeout_ms, label }`.
   - `label` **must** be `1..=64` UTF-8 bytes with no ASCII/Unicode control characters and **must never** contain a tenant identifier (`OPS-020`, `RTE-078`). Store the returned `BranchSlot` in the execution layer's branch handle table (`register` is idempotent and never reuses `BranchSlot` indexes).

2. **Replica Selection & Breaker Admission (hot path, zero heap allocation):**
   - Read `let now = registry.now();` once per request/attempt (`INV-02`).
   - Filter capability-group members by caller-owned `RTE-073` predicates (`BranchStatus::Active`, policy `Execute`, principal `trust`, required capabilities) or `RTE-076` sticky session affinity.
   - Resolve `&TelemetrySlot` references via `registry.get(branch_slot)` and call `XorShift64::with_thread_local(|rng| select(&candidates, now, rng))` (`RTE-074`, `RTE-079`).
   - **Important (`RTE-079(e)`, `RTE-085`, T-1):** `registry.maintain()` only resets stale EWMAs and stale breaker buckets — it does **not** advance `Open -> HalfOpen` breaker timers (only `admit`, `state`, `flapping`, `record`, and `apply_health` advance timers). Consequently, `gap-balance`'s selector (`select` / `select_excluding` via `Breaker::is_selectable_readonly`) intentionally treats an `Open` member whose open timer has elapsed (`!not_serving && now.ms >= open_until`) as selectable without mutating state; **do not** pre-filter candidates by cached `BreakerState::Open` in `WP-M3-04`, because letting `select` pick an elapsed-timer `Open` member is what allows the first request after `open_until` to call `slot.breaker().admit(now)`, advance `Open -> HalfOpen`, and take the episode's `ProbePermit`.
   - `select` is read-only (`RTE-079(e)`): immediately call `slot.breaker().admit(now)` on the chosen candidate:
     - `Admission::Allowed`: acquire `let _in_flight = InFlightGuard::acquire(&slot_arc);`. If this is the initial attempt (not a retry or hedge), call `slot.on_first_attempt()`. Dispatch the upstream call; on completion call `slot.record(outcome, elapsed, registry.now())`.
     - `Admission::Probe(permit)`: acquire `let _in_flight = InFlightGuard::acquire(&slot_arc);` (and `slot.on_first_attempt()` on initial attempt). Dispatch the upstream call; on completion, if updating EWMAs for the probe sample as well, call `slot.record(outcome, elapsed, registry.now())` **before** `permit.record(outcome, elapsed, registry.now())` (while state is still `HalfOpen`, `slot.record` updates EWMAs only and never touches the `Closed` window; `permit.record` then updates the 3-probe majority tally and clears the window if transitioning `HalfOpen -> Closed`). If the request future is cancelled or times out before `permit.record`, dropping `_in_flight` and `permit` automatically decrements `in_flight` and frees the probe slot (`RTE-071`, `RTE-085`).

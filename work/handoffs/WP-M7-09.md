# Handoff — WP-M7-09: Conditional: columnar list extension (X-1)

## Summary of Changes
- Implemented lock-free, lossless `ColumnarTable`, `PayloadSavings`, and `ColumnarError` in [`crates/gap-exec/src/columnar/mod.rs`](../../crates/gap-exec/src/columnar/mod.rs):
  - `ColumnarTable::from_parts`: validates unique column names and uniform row widths.
  - `ColumnarTable::from_homogeneous_objects`: deterministically sorts columns and enforces identical object key sets across all rows for strict lossless reconstruction.
  - `ColumnarTable::to_objects`: expands columnar rows back into `Vec<serde_json::Value>` objects.
  - `ColumnarTable::measure_compact_json_savings`: compares compact JSON byte footprint between row-oriented objects and columnar layout.
  - Unit tests (`// spec: GQL-003`): round-trip losslessness, empty/non-object/heterogeneous/duplicate-column/width-mismatch error checks, and 100-row homogeneous payload byte reduction check (`> 40%` on synthetic dense objects).
- Authored formal decision record [`docs/decisions/x1-columnar.md`](../../docs/decisions/x1-columnar.md) closing wire activation of `@format(as: COLUMNAR)` for `1.0-RC` because `WP-M7-05` GAP-Bench measurements show `< 20%` suite-level end-to-end token savings (`api_lookup`, `cross_branch_join`, `code_graph` are dominated by progressive discovery and server-side joins/traversal rather than repeated array object keys), while retaining `gap_exec::columnar::ColumnarTable` for post-1.0 evaluation.

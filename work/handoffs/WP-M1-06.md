Design notes & brief recordings (`work/context/m1-06-brief.md`):
  1. [`plan_hash` vs RFC 8785 JCS (`Brief §3.5`)]:
     RFC 8785 JCS canonicalization lives in `gap-snapshot::canonical` (`L3`) and cannot be imported
     from `gap-plan` (`L2`, verified by `tools/check_layers.py`). `plan_to_value` serializes `Plan`
     into `serde_json::Value` where `serde_json::Map` is backed by `BTreeMap` (no `preserve_order`
     feature in the workspace; asserted in `run_010_ir_nodes_roundtrip_serde_and_serde_json_map_sorts_keys`),
     `plan_compact_json` emits compact sorted JSON, and `plan_hash` computes the 64-char hex `blake3`
     digest. Plans contain no floating-point fields unless a GraphQL float literal argument is passed.
  2. [`gap_core::snapshot::Capabilities` pagination/order flags (`Brief §1`)]:
     `gap_core::snapshot::Capabilities` currently carries `foreach_batch`, `idempotency`, `dry_run`,
     `subscriptions`, `tasks`, `sketch`, `explain`, and `predicate_ops`, with no pagination or
     `order_by` flags yet (`proto/gap/ngc/v1/ngc.proto` fields 3-4). `Pushdown { limit, order_by,
     predicate }` is declared on `Fetch` and left empty (`Pushdown::default()`) in `WP-M1-06`;
     populating pagination/order/predicate pushdown is recorded for `WP-M3-02`.
  3. [`@skip` and `@include` directive handling (`Brief §4`)]:
     `@skip(if:)` and `@include(if:)` directives on root fields, nested fields, inline fragments, and
     named fragment spreads are **kept** variable-independently on `Fetch.directives` and
     `SelectionField.directives` (`SelectionDirective { name, if_arg: ArgValue }`, inheriting
     enclosing fragment conditional directives onto flattened selections) rather than evaluated at
     plan time, preserving 100% variable-independence of cached plans (`Brief §3.2`).
  4. [Refused operations & built-in root fields (`Brief §1`, `§3.3`)]:
     Mutations (`Mutate` is declared only in IR), subscriptions, and GAP built-in / discovery /
     introspection root fields (`gap`, `__search`, `__metaGraph`, `__schema`, `__type`, `__typename`,
     `gapTaskEvents`) are refused with `ErrorCode::UnsupportedFeature` (`GAP_UNSUPPORTED_FEATURE`)
     and explicit diagnostic messages. Root fields with no owner in `snapshot.ownership` (or no
     matching `OpKind::Query` operation on the owning branch) fail with `ErrorCode::UnknownField`
     (`GAP_UNKNOWN_FIELD`, `RUN-011`).
  5. [`moka` coalescing guarantee & byte weigher (`Brief §3.6`, `§4`)]:
     `PlanCache::get_or_plan_with` uses `moka::sync::Cache::entry(key).or_try_insert_with(...)`,
     which coalesces concurrent misses for the same `PlanCacheKey` into **at most one** successful
     `init` evaluation per cold/expired key (`entry.is_fresh() == true` -> `PlanCacheStatus::Miss`,
     coalesced waiters -> `PlanCacheStatus::Hit`; failed `init` calls are never cached). Verified
     with 64 threads synchronized on a `std::sync::Barrier` (`init_calls == 1`). Because `moka`'s
     `.weigher(...)` makes `.max_capacity(...)` bound total byte weight rather than entry count,
     `PlanCacheConfig` exposes `max_entries = 10_000`, `ttl = 3_600 s`, and `max_weight_bytes:
     Option<u64>` (defaulting to `max_entries * 4_096` bytes when `None`, or exact byte cap when `Some`).
     `PlanCache::get_or_plan` also re-runs `gap_ql::enforce_operation_cost` on warm hits so an
     over-budget variable set or caller `@budget` is always rejected (`RUN-005`).

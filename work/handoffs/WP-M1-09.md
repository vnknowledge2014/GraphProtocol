## What it is

A thin JSON-RPC MCP client (no `rmcp`) exposed as an NGC connector. It speaks the stateless `2026-07-28` era first (`server/discover`, `_meta` on every request,
`Mcp-Method`/`Mcp-Name` headers) and falls back to the stateful `2025-11-25` era (`initialize`, `notifications/initialized`, `MCP-Session-Id`, one re-initialisation on `404`,
`DELETE` on close). Tools become `QUERY` operations unless an admin classification says otherwise; annotations are untrusted strings that never change a kind or a side-effect
hint (ADR-015). Resources become the node category `McpResource`, readable through the reserved operation `mcp_read_resource(uri)`. `foreach` is emulated (bounded fan-out,
`max_batch_size = 64`, `upstream_calls` counts the requests actually sent). Server text only enters an error after sanitising, clipping and redaction of the connector's own secrets.
`stdio` children start only through an allow-list entry (absolute path + pinned sha256, cleared environment, no shell, kill on drop); `LaunchPolicy::Refuse` is the default.

## Decisions and deviations

* **`rmcp` (ADR addendum, proposed text).** "WP-M1-09 could not evaluate `rmcp` 3.7 against MCP 2026-07-28: the crate is not vendored and the work package is offline. A thin JSON-RPC client
  was implemented instead (`gap-mcp::outbound`). `rmcp` would have to support: stateless requests with `params._meta` protocol version and client capabilities on every request, the `Mcp-Method`/`Mcp-Name`
  routing headers, `server/discover`, `resultType`/`ttlMs`/`cacheScope` envelopes, cancellation by closing the HTTP stream (HTTP) versus `notifications/cancelled` (stdio), omission of `roots`/`sampling`
  from client capabilities, and a legacy `2025-11-25` fallback behind one connector. Re-evaluate when `rmcp` is vendored."
* **Caching hints are lenient.** The pinned caching page says a client SHOULD treat an absent `ttlMs` as 0: an absent/negative `ttlMs` is stored as 0 and an absent/unknown `cacheScope` as `private`;
  `resultType` stays mandatory in the modern era (SPEC-NOTES section (c)).
* **Whole-number doubles.** Protobuf `Struct` numbers are doubles; whole numbers are sent upstream as integers (`7.0` -> `7`), otherwise strict `integer` schemas reject them (found by the connector tests).
* **Arguments are validated before sending** against the tool's `inputSchema` (`required`, property types, enums, array items, `additionalProperties: false`); the server validates the rest. This is what makes `errors.mapping` of the kit pass with `INVALID_ARGUMENT`.
* **Out of scope, recorded as follow-ups:** the real sandbox (WP-M6-09), TLS and OAuth, MRTR/elicitation (an `input_required` result is `UPSTREAM_ERROR`, never silently dropped), `subscriptions/listen`
  and `listChanged` push (only `refresh()` exists, drift scheduling is WP-M6-10), prompts, `Mutate` for admin-classified tools (they are described, a `Query` of them is `INVALID_ARGUMENT`, `Mutate` is `UNIMPLEMENTED`), registration in `gap-server` (WP-M1-12).

# Handoff: WP-M6-06 — Tenant isolation enforcement and cross-tenant fuzz

## What Changed

- Added cross-tenant isolation property/fuzz and security enforcement tests in `tests/security/tenant/tenant_isolation.rs`, exposed as an integration test target via `crates/gap-server/tests/tenant_isolation.rs` so `cargo nextest run --test tenant_isolation` executes the suite.
- Verified `INV-09` and `TM-09` across 32 random distinct `(tenant_a, tenant_b)` pairs over:
  - `SqliteContextStore` (`put_node`, `put_edge`, `get_node`, `counts`, `search_nodes`, `traverse`, `delete_node`)
  - `InMemoryTaskStore` and `SqliteTaskStore` (`put_task`, `get_task`, `list_tasks`, `events_from`, `renew_lease`)
  - `InMemoryIdempotencyStore` and `SqliteIdempotencyStore` (`check_or_reserve`, `complete`, `get`)
  - `SqliteFeedbackStore` (`record_discovery`, `get`, `attribute_server_execution`) and `AuditChain` (`Tenant(scope_a)` vs `Tenant(scope_b)` vs `System`)
  - `PlanCache` (`PlanCacheKey::from_snapshot` over tenant-scoped `Snapshot`)
  - `CompiledPolicySet` (default Cedar policies denying cross-tenant `Discover`/`Execute`/`Traverse`/`Mutate`)
  - `TelemetryRegistry` (`TelemetrySlotKey` and failure EWMA isolation per `(tenant, branch_uid)`)
- Added `SEC-010` regression test proving `derive_authenticated_principal` keeps the credential's `TenantId` and records mismatch metadata when untrusted `X-Tenant` or body `tenant` hints conflict, and Cedar permits cross-tenant admin evaluation only when `admin:impersonate` scope is explicitly granted.
- Added `INV-19` negative compile-fail test invoking `rustc --edition 2024` against compiled `libgap_store` artifacts (validated against a passing positive control) to prove forging `TenantScope` from `TenantId` fails (`E0423`/`E0603`), passing `&TenantId` instead of `&TenantScope` fails (`E0308`), and omitting `&TenantScope` on `TaskStore`/`IdempotencyStore` fails (`E0061`/`E0308`).

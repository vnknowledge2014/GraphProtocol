Course 1: Lift-Off — First Supergraph

Course 1 takes you from an empty terminal to a live two-branch supergraph combining an OpenAPI shop service and an MCP notes server behind /graphql and /mcp.

What you'll learn

  • Scaffold starter files with ./target/dist/gap init and understand BLAKE3 key digests.
  • Run fail-closed validation (gap config check and gap doctor) before starting listeners.
  • Query OpenAPI Objects and MCP JSON scalars together without hitting GAP_UNKNOWN_FIELD.

Lesson 1: Scaffolding a Workspace (gap init)

Course 1: Lift-Off · 20 min · 4 lessons 0 / 4 completed
1Scaffold2Config & Doctor3Boot & Probe4Joined Query

In real production setups, you never hand-write TOML boilerplate from scratch. Running gap init creates a ready-to-edit 5-file starter layout containing gap.toml, a sample OpenAPI spec, fixture scripts, and a development bearer token hashed with BLAKE3-256:

Zero Raw Keys in Config Files

gap.toml stores only key_hash = "8a7d..." (for key gap_dev_skeleton_key_01 in Walking Skeleton). GAP verifies incoming Authorization: Bearer ... tokens using constant-time BLAKE3 comparison and redacts secrets cleanly (INV-15).

Key Takeaways

  • gap init <dir> generates a working starter supergraph cleanly.
  • gap.toml stores BLAKE3 hashes (key_hash), never plaintext production tokens.

Lesson 2: Wiring OpenAPI & MCP Branches (gap config check & doctor)

Open examples/walking-skeleton/gap.toml. Notice two [[branches]] entries: id = "shop" (OpenAPI 3.0 on port 9101) and id = "notes" (MCP HTTP on port 9102/mcp). Validate both files and OS readiness before running traffic:

Key Takeaways

  • gap config check fails closed on invalid schemas, ports, or missing files.
  • gap doctor audits sockets, branch file paths, API keys, and sandbox readiness.

Lesson 3: Booting Fixtures & Probing /readyz

Start the two lightweight Python upstream fixtures first, then launch gap serve and inspect /healthz and /readyz:

/readyz returns {"status":"ready","generation":1} only after snapshot generation 1 compiles and binds into the lock-free ArcSwap pointer.

Key Takeaways

  • /healthz tracks process liveness; /readyz turns ready only once Snapshot generation >= 1 compiles.
  • Alternatively, click Start Live Lab inside the Interactive Lab page to automate all 3 processes.

Code Challenge

Fix the Query Parameter Name

Complete the cross-branch query so both shop customer #1 and MCP notes for customer #1 resolve together (remember: customer_notes is a JSON scalar!). What argument name goes inside customer_notes(____: 1)?

query {
  customer(id: 1) { id name tier }
  customer_notes(____: 1)
}

Knowledge Check

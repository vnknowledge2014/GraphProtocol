Khóa 1: Lift-Off — Siêu đồ thị Đầu tiên

Khóa 1 đưa bạn từ màn hình terminal trống tới một siêu đồ thị chạy thật gồm hai nhánh: cửa hàng REST OpenAPI (shop) và máy chủ MCP (notes) sau cổng /graphql và /mcp.

Bạn sẽ nắm được gì

  • Khởi tạo bộ khung dự án mẫu bằng ./target/dist/gap init và hiểu cơ chế băm khóa BLAKE3.
  • Chạy kiểm định cấu hình chặt fail-closed (gap config check và gap doctor) trước khi mở cổng.
  • Truy vấn gộp Object OpenAPI và scalar JSON MCP mà không dính lỗi GAP_UNKNOWN_FIELD.

Bài 1: Khởi tạo Workspace Mới (gap init)

1Khởi tạo2Config & Doctor3Bật & Kiểm tra4Truy vấn Gộp

Trong thực tế triển khai, bạn không cần tự gõ cấu hình TOML từ đầu. Lệnh gap init tạo ngay bộ khung 5 tệp tiêu chuẩn gồm gap.toml, đặc tả OpenAPI mẫu, kịch bản fixture giả lập và mã khóa Bearer phát triển băm sẵn bằng BLAKE3-256:

Không bao giờ lưu Secret gốc trong Cấu hình

Tệp gap.toml chỉ chứa key_hash = "8a7d..." (ứng với khóa dev gap_dev_skeleton_key_01 trong Walking Skeleton). Cổng GAP kiểm chứng header Authorization: Bearer ... bằng phép so khớp BLAKE3 hằng thời gian và tự động che mọi bí mật (INV-15).

Điểm Cốt lõi Cần Nhớ

  • gap init <dir> sinh bộ dự án mẫu đầy đủ chỉ trong 1 giây.
  • gap.toml chỉ lưu giá trị băm BLAKE3 (key_hash), tuyệt đối không chứa token thô ở bản production.

Bài 2: Kết nối Nhánh OpenAPI & MCP (gap config check & doctor)

Hãy mở examples/walking-skeleton/gap.toml. Bạn sẽ thấy hai khối [[branches]]: id = "shop" (OpenAPI 3.0 chạy ở cổng 9101) và id = "notes" (MCP HTTP tại cổng 9102/mcp). Kiểm tra cú pháp cấu hình và điều kiện môi trường trước khi chạy:

Điểm Cốt lõi Cần Nhớ

  • gap config check từ chối khởi động ngay nếu phát hiện cấu hình, cổng mạng hoặc đường dẫn tệp sai.
  • gap doctor kiểm tra toàn diện socket, quyền đọc nhánh, API key và trạng thái sandbox hệ điều hành.

Bài 3: Khởi động Dịch vụ Upstream & Kiểm tra /readyz

Chạy hai tiến trình giả lập upstream bằng Python trước, rồi bật gap serve và thăm dò trạng thái /healthz cùng /readyz:

Điểm cuối /readyz chỉ trả về {"status":"ready","generation":1} sau khi Snapshot thế hệ 1 biên dịch hoàn tất và nạp nguyên tử vào con trỏ không khóa ArcSwap.

Điểm Cốt lõi Cần Nhớ

  • /healthz báo tiến trình còn sống; /readyz chỉ xanh khi Snapshot generation >= 1 đã biên dịch xong.
  • Bạn cũng có thể bấm nút Bật Lab Thực Hành trong trang Phòng Lab để khởi chạy tự động cả 3 tiến trình.

Bài 4: Truy vấn Gộp Liên Nhánh Đầu Tiên & Thực hành Điền mã

Bây giờ hãy gửi một yêu cầu POST /graphql duy nhất vừa lấy khách hàng số 1 và các đơn hàng từ nhánh REST shop, vừa đọc ghi chú từ nhánh MCP notes:

Thử thách Điền mã

Hoàn thiện Tên Tham số Truy vấn MCP

Điền đúng tên tham số vào customer_notes(____: 1) để khớp hợp đồng của nhánh MCP notes (lưu ý: customer_notes trả về scalar lá JSON):

query {
  customer(id: 1) { id name tier }
  customer_notes(____: 1)
}

  • Một request POST /graphql duy nhất chạy đồng thời sang cả nhánh REST và MCP.

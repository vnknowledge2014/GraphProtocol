Định tuyến System-1 & HTTP/3 QUIC

GAP tách biệt hoàn toàn các mô hình quyết định System-1 tùy chọn (@receptron/laya, TypeSafe Jev, Google gemini-decision-1) khỏi đường thực thi nóng, đồng thời hỗ trợ HTTP/2 + HTTP/3 QUIC tắt 0-RTT.

Bạn sẽ nắm được gì

  • Vì sao GAP vận hành mặc định với BASELINE_FALLBACK thay vì mô hình neural chưa tinh chỉnh (G-S1).
  • Cách bật nhà cung cấp [router] có kiểm soát egress và che bí mật.
  • Cấu hình HTTP/3 QUIC (RFC 9114) an toàn với chế độ prod fail-closed TLS.

Nếu bất kỳ provider System-1 nào (@receptron/laya, TypeSafe jev /v1/systemone hoặc Google gemini_decision_1) bị tắt, quá hạn hay trả định dạng lỗi, hệ thống tự động rơi về bộ định tuyến nền tất định mà không bao giờ làm sập request hay ảnh hưởng Cedar.

Dual-Stack HTTP/2 + HTTP/3 trên QUIC (OPS-005, ADR-026)

Khi khai báo trong gap.toml, crate gap-transport mở song song TCP HTTPS (HTTP/1.1 + HTTP/2 kèm header Alt-Svc: h3=":8443"; ma=86400) và UDP QUIC (quinn + h3, TLS 1.3 ALPN h3):

  • Chống Replay Attack: Thiết lập max_early_data_size = 0 để tắt hoàn toàn TLS 1.3 0-RTT trên QUIC, ngăn chặn phát lại các thao tác thay đổi dữ liệu.
  • Fail-Closed ở prod: Nếu chạy profile = "prod" có http3_listen nhưng thiếu chứng chỉ tls_cert_secret / tls_key_secret, cổng từ chối khởi động ngay; ở profile = "dev", hệ thống tự sinh chứng chỉ TLS 1.3 tự ký tạm thời nếu chưa truyền file chứng chỉ.
  • Hiệu năng đo thực tế: Đạt 5.013,1 req/s qua kết nối QUIC đa luồng (1,626 ms p50 / 2,364 ms p95 / 0 lỗi) song hành cùng 1.063,6 req/s qua TCP HTTP/1.1+2 (11,544 ms p95).

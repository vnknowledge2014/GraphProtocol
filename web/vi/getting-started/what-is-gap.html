GAP là gì?

GAP cấp cho AI Agent một cổng vào duy nhất, an toàn và định kiểu chặt để gọi REST API, SQL, gRPC, GraphQL, CLI và kho mã nguồn — không cần nhồi hàng trăm nghìn tokens JSON vào prompt.

Bạn sẽ nắm được gì

  • Vì sao cách nạp phẳng toàn bộ schema công cụ vào LLM sẽ vỡ trận khi mở rộng quy mô.
  • 5 thuật ngữ cốt lõi trong GAP: Gateway, Branch, Connector, Snapshot và Principal.
  • Ngưỡng giao cắt thực tế: khi nào Direct-MCP gọn hơn và khi nào GAP áp đảo.

Vì sao Mô hình Tool Phẳng Gặp Giới hạn

Phần lớn hệ thống agent hiện tại nối thẳng LLM tới hàng loạt máy chủ MCP hoặc API rời rạc. Cách này chạy ổn với 5–10 công cụ, nhưng nhanh chóng gặp 4 điểm nghẽn khi đưa vào vận hành thật:

  • Bùng nổ Ngữ cảnh Prompt: Tải sẵn 1.000 mô tả JSON Schema tốn tới 203.421 tokens ngay trước khi người dùng kịp đặt câu hỏi.
  • Vòng lặp Thác nước N+1: Thiếu bộ lập kế hoạch gom khóa, LLM tự gọi lấy danh sách khách hàng rồi lại lặp tuần tự từng lượt cho đơn hàng và ghi chú — vừa chậm vừa tốn token.
  • Mô tả Tool Biến đổi (Rug Pull): Nếu một MCP server bên ngoài lén sửa mô tả công cụ sau khi admin đã duyệt để gài lệnh độc, client phẳng sẽ chuyển thẳng chuỗi đó cho mô hình.
  • Phân quyền Xác suất Kém An toàn: Để mô hình ML hay LLM quyết định quyền truy cập ngay trên đường nóng luôn tiềm ẩn rủi ro qua mặt; phân quyền bắt buộc phải là mã nguồn tất định.

Khi nào Direct-MCP vẫn Ít Token hơn (Đối chứng Trung thực)

Kết quả Đối chứng Trung thực (ADR-021)

Nếu hệ thống chỉ có tối đa 50 tool đơn giản dạng đọc 1 bước và nhà cung cấp LLM giữ Prompt Prefix Cache 0,10x luôn ấm, Direct-MCP tốn ít token hơn ở câu gọi đơn (547,2 so với 4.691,9 tokens ở N=10).

Ngược lại, GAP vượt trội hoàn toàn khi số tool tăng từ ~200 trở lên, khi có join đa nhánh, duyệt đồ thị mã nguồn, hoặc khi yêu cầu bảo mật chặt (duyệt mutation Cedar, chống SSRF, đóng băng rug-pull). Xem trực quan tại Bộ tính Crossover.

Native Graph Connectors (NGC)

Native Graph Connectors (NGC) let you project existing REST APIs, SQL databases, gRPC services, GraphQL subgraphs, CLIs, and AST codebases into one unified graph without hand-writing glue resolvers.

What you'll learn

  • Walk through connecting an OpenAPI REST endpoint declaratively using x-gap-in-param.
  • Compare all 6 shipped NGC adapters and their batching/sandbox behavior.
  • How Propose-Not-Activate validates joins before any live traffic sees a new schema.

How a REST API Becomes a Graph Branch

Given an upstream REST endpoint like GET /customers/{id} paired with list batching GET /customers?ids=1,2,3, declare the "x-gap-in-param" extension inside your OpenAPI operation (verbatim from examples/walking-skeleton/shop.openapi.json):

Then wire the OpenAPI file into gap.toml:

  • id = "shop": Stable branch identifier scoping generated GraphQL types (shop_CustomersResult, shop_OrdersResult) and audit logs.
  • trust = "T1": Admin-approved branch whose OpenAPI spec_hash and operation desc_hash are cryptographically pinned against silent mutations.

Safe Activation: Propose-Not-Activate & @join Verification

Newly ingested schemas never auto-publish directly into request execution. Instead, gap ingest once compiles a Candidate Intermediate Schema Graph (CISG), runs sample data verification on proposed @join edges (checking containment & null rates, never LLM guesswork), and queues a Proposal for operator review:

Arguments, Mutations & Joins

Master filtering with variables, writing safely via @sideEffect mutations, resolving cross-branch joins in batches, and translating REST or Direct-MCP habits into clean GAP workflows.

What you'll learn

  • Pass typed GraphQL variables instead of string formatting so PlanCache reuses compiled query plans safely.
  • Distinguish query (read-only) from @sideEffect mutation calls gated by dry_run and Cedar two-person rules.
  • Map every REST / Direct-MCP concept you already know to its exact counterpart in GAP.

Arguments & Parameterized Variables (PlanCache Reuse)

Just like query parameters in a REST URL, GraphQL fields accept typed arguments such as customer(id: 1) or orders(customer_id: 1). Never concatenate user or LLM inputs directly into query text—declare strongly typed variables ($cid: Int!):

  • Zero Injection: Typed variables prevent syntax smuggling inside query strings.
  • Hot Cache Hits: Because the query text stays identical across customers, GAP reuses the compiled plan in PlanCache keyed by (TenantId, snapshot_generation, query_hash) (INV-09).

Mutations & @sideEffect Safety Rails

While query operations read data cleanly across snapshots, state-changing actions must use mutation (or MCP tool gap_mutate) annotated with @sideEffect:

GAP @sideEffect levels from spec/02-gap-ql.md §5 and Cedar enforcement
SideEffectLevelMeaningDefault Cedar Policy Behavior
NONERead-only lookup with no state change.Permitted for authorized Read principals.
REVERSIBLEDraft update or compensating write (can undo).Allowed with Mutate permission; logged to BLAKE3 ledger.
IRREVERSIBLE / UNKNOWNPayment transfer, ledger delete, or unverified tool.Blocked unless context.approved && context.approverIsDifferent holds.

GAP for REST & Direct-MCP Developers (Translation Table)

You do not throw away your existing REST APIs or MCP servers to adopt GAP—you keep them running unchanged and mount them as declarative NGC branches.

Going deeper: Why did GAP choose standard GraphQL instead of a brand-new query language?

Per GQL-001 and spec/02-gap-ql.md, inventing custom keywords like traverse would break every IDE highlighter, schema linter, and validation library. Using 100% standard GraphQL lets GAP validate queries with Apollo's Rust apollo-compiler, pass 136/136 differential conformance checks against graphql-js 16.13.2, and express federation cleanly with @join and @sideEffect directives.

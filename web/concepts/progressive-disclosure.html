Progressive Disclosure (651 Tokens)

Instead of streaming up to 203,421 JSON schema tokens into the prompt upfront, GAP holds MCP tools/list at a fixed 651 tokens and reveals schemas across three progressive levels (L0 -> L1 -> L2).

What you'll learn

  • How Level 0 (__metaGraph), Level 1 (__search), and Level 2 (__type) work step-by-step.
  • Why permission filtering happens BEFORE search scoring (INV-05).
  • Inspect real payload sizes returned at each discovery hop.

Walkthrough: From Intent to Typed Query

  1. 1

    L0 — Branch Overview (__metaGraph / gap_describe)

    The agent first requests a concise capability directory capped at <= 24 tokens per branch:

    • Returned summary: shop (openapi, 4 ops), notes (mcp, 1 op)—hundreds of branches stay legible in a few hundred tokens.
  2. 2

    L1 — Authorized Hybrid Search (__search / gap_search)

    The agent searches top-k matching operations using hybrid BM25 + HNSW vectors. GAP applies the caller's Cedar visibility bitset first (INV-05), so forbidden operations never appear in candidate lists or token counts:

  3. 3

    L2 — On-Demand Type Hydration (__type)

    Only after choosing operations does the agent inspect the exact GraphQL input and return fields needed to build its query:

Security Guarantee: Visibility Filtering Before Ranking (INV-05)

No Existence Leakage

If a restricted tenant or unprivileged agent queries __search, restricted branches and operations are masked out via the per-principal visibility bitset before scoring, ranking, or returning total counts.

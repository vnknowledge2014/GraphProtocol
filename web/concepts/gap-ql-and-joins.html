GAP-QL & Batched Joins

GAP-QL compiles strictly valid GraphQL parsed by apollo-compiler and eliminates N+1 client round-trips with bounded DataLoader key batching (INV-18).

What you'll learn

  • Why modeling discovery as __metaGraph/__search/__type preserves GraphQL parser compatibility.
  • How GAP deduplicates join keys to dispatch ceil(unique_keys / max_batch) upstream calls (INV-18).
  • Full GAP-Bench token matrix across N in {10, 50, 200, 1000}.

Zero Custom Keywords (GQL-001)

Instead of inventing non-standard GraphQL syntax like traverse { ... }, GAP exposes discovery and federation via standard schema root fields and validated directives from spec/02-gap-ql.md §5 (@join, @sideEffect, @auth, @pii). Every query passes apollo-compiler validation and differential testing against graphql-js 16.13.2.

Preventing N+1 Waterfalls (INV-18)

Suppose a cross-branch query fetches 50 customers and joins their notes from an external MCP or SQL branch. Flat RPC loops fire 50 separate network requests. GAP extracts unique keys, enforces bounded chunks, and sends at most ceil(unique_keys / max_batch) BatchQuery frames—validated on every CI run (VER-040).
